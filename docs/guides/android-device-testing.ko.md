# Android 개발 APK와 실기기 테스트

이 안내는 **개발용** Account Book Dev 앱을 위한 것이다. 스토어 설치본이나 실금융정보 베타가 아니다. APK 생성과 휴대폰에서 로그인/거래가 정상 동작함은 다른 검증 단계다.

2026-10-19 개발 APK를 생성했고, 2026-10-20 [HTTPS 테스트용 APK](../../output/android-apk/account-book-dev-https-arm64.apk)로 업데이트했다. Android 16 실기기에서 합성 계정 로그인·수기 입출금 저장·PC 동일 기록 조회와 두 번째 계정 격리까지 확인했다. [최신 검증 기록](../status/2026-10-20-android-https-device-test.ko.md)에 파일 해시·서명·개발 인증서 범위와 남은 시험이 있다. 운영 계정이나 금융 알림 수집까지 검증된 것은 아니다.

## 사용자가 먼저 준비할 것

1. 갤럭시의 **설정 → 휴대전화 정보 → 소프트웨어 정보 → 빌드번호**를 7번 눌러 개발자 옵션을 켠다. 기기에 따라 잠금 해제가 필요하다.
2. **설정 → 개발자 옵션 → USB 디버깅**을 켠다.
3. 데이터 전송이 가능한 USB 케이블로 이 PC에 연결한다. 충전 전용 케이블은 안 된다.
4. 휴대폰의 **USB 디버깅을 허용하시겠습니까?** 창에서 현재 연결한 신뢰하는 PC인지 확인한 뒤 허용한다. 모르는 PC에서는 허용하지 않는다.
5. 연결 후 “기기를 연결했고 USB 디버깅을 허용했어”라고 알려준다. 이후 adb 인식·APK 설치·개발 서버 연결은 개발자가 진행한다.

자동 차단/회사 관리 정책이 설치를 막으면 오류 화면을 먼저 확인한다. 백신/Play Protect/회사 정책을 무조건 끄지 않는다. 필요한 제조사 USB 드라이버가 없는 경우에만 공식 드라이버를 확인한다. 테스트 후 USB 디버깅을 끄거나 디버깅 승인을 취소해도 된다.

## 개발 APK가 실행되는 구조

### 사용자가 직접 다시 열 때

PC 서버가 켜져 있고 USB 개발 연결이 유지돼 있으면 설치된 **Account Book Dev**를 열면 된다. 개발 서버 선택 화면이 나오면 `http://localhost:8081`을 선택한다. 은행 알림 접근은 단순 화면/수기 장부 확인에 필요하지 않다. PC 종료나 USB 연결 초기화 후에는 서버와 포트 연결을 다시 준비해야 한다. 외출 중 사용은 별도 독립 APK/외부 HTTPS 서버 단계다. [현재 동의 서버 단계와 실행 조건](../status/2026-10-21-server-notification-consent.ko.md)을 참고한다.

PC 서버는 그대로 켜져 있고 USB만 다시 연결했다면 이 PC의 PowerShell에서 다음 명령으로 두 연결을 복구할 수 있다. 연결된 Android 기기가 정확히 한 대이고 디버깅 승인을 한 상황에만 실행한다. 앱을 다시 설치하거나 알림 접근을 허용하는 명령은 아니다.

```powershell
$adb = "$env:LOCALAPPDATA/account-book-android/sdk/platform-tools/adb.exe"
& $adb devices
& $adb reverse tcp:3000 tcp:3000
& $adb reverse tcp:8081 tcp:8081
```

`unauthorized`라면 휴대폰에서 이 PC의 디버깅 승인을 확인한다. 기기가 0대이거나 2대 이상이면 이어서 실행하지 않는다. PC 서버가 꺼졌거나 개발 인증서가 만료됐다면 이 연결 명령만으로는 해결되지 않으며 테스트 환경을 먼저 다시 준비해야 한다.

### 연결 구조

화면 코드 수신: `휴대폰의 개발 APK ↔ PC의 Metro(USB 8081)`

장부 API 요청: `휴대폰의 개발 APK → 테스트 BFF HTTPS → 테스트 장부 서버`

Metro가 금융 API 요청을 대신 보내는 구조가 아니다. 두 연결을 각각 준비해야 한다.

- APK의 네이티브 껍데기는 한 번 설치하고 화면 코드는 Metro에서 받는다. PC를 끄면 이 개발 방식으로 계속 사용할 수 없다.
- Metro 개발 전송은 USB의 `adb reverse tcp:8081 tcp:8081`로 연결할 수 있다. 이는 금융 API를 HTTP로 바꾼다는 뜻이 아니다.
- 금융 API는 `EXPO_PUBLIC_API_ORIGIN`에 지정한 **신뢰 가능한 인증서의 HTTPS origin**을 사용한다. `/api` 같은 경로는 붙이지 않는다.
- 휴대폰의 localhost는 기본적으로 휴대폰 자신이다. PC localhost 인증서를 PC에서만 신뢰 등록했다고 휴대폰도 신뢰하는 것은 아니다. USB reverse로 포트를 연결해도 TLS 신뢰 문제는 남는다.
- 공인 인증서가 있는 테스트 BFF가 없으면 서버 연결 준비가 별도로 필요하다. 인증서 검증 무시·운영 DB 키를 앱에 넣는 우회는 하지 않는다. 공개 터널이나 배포를 임의로 만들지 않는다.
- 이번 USB 시험은 단기 CA를 APK의 debug/localhost 범위에만 넣어 해결했다. API origin은 `https://localhost:3000`, USB reverse는 3000과8081이다. 일반 브라우저의 인증서 경고를 무시하는 사용자 절차는 권장하지 않는다. 테스트 인증서가 만료되면 새 인증서·APK 준비가 필요하다.
- 자동 수집은 아직 구현되지 않았다. 수기 시험에는 알림 접근을 켤 필요가 없다. 10/21 후속의 **동의·권한 왕복 시험에서만** 아래 새 APK로 Account Book Dev의 알림 접근을 직접 허용/해제한다. 다른 앱의 권한이나 시스템 보안 정책을 일괄 변경하지 않는다.
- 개발 빌드에는 디버거·네트워크 검사 기능이 들어 있다. 합성 테스트 계정만 사용하며 APK나 개발 서버를 외부 사용자에게 공개하지 않는다. 개발용 HTTP 허용과 화면 위 표시 권한이 템플릿에 포함되므로 운영 배포본의 권한·네트워크 정책과 혼동하지 않는다.

## 개발자가 수행할 설치·연결

아래의 APK 경로와 도구 버전은 동봉한 상태 문서의 검증 결과를 따른다. 여러 기기가 연결돼 있으면 의도한 기기를 명시해서 설치한다. 기기 식별자는 공개 문서에 기록하지 않는다.

```powershell
$sdk = "$env:LOCALAPPDATA/account-book-android/sdk"
& "$sdk/platform-tools/adb.exe" devices -l
# 확인한 기기 하나만 연결된 상황에서:
& "$sdk/platform-tools/adb.exe" install -r '<검증된 개발 APK 경로>'
& "$sdk/platform-tools/adb.exe" reverse tcp:8081 tcp:8081
```

저장소 루트에서 Node22/pnpm 환경과 공개 테스트 origin을 준비한 뒤:

```powershell
pnpm --filter @account-book/mobile start --localhost
```

개발 클라이언트의 서버 연결 화면에서 Metro 주소를 선택한다. USB 연결 방식이면 `http://localhost:8081`을 사용한다. Expo Go 대신 **Account Book Dev** 앱을 연다. 테스트 origin이 미설정이면 장부 앱의 인증 기능을 확인할 수 없다.

APK를 휴대폰으로 복사해서 직접 설치할 수도 있으나 파일 앱의 '알 수 없는 앱 설치' 승인이 필요할 수 있다. USB 디버깅 설치를 기본 경로로 하고 광범위한 설치 권한을 미리 켜지 않는다.

Windows 도구가 한글 경로를 처리하지 못하면 개발자는 동일 해시의 빌드 원본 `C:/Users/PC/a3/apps/mobile/android/app/build/outputs/apk/debug/app-debug.apk`로 설치한다. 파일명이나 위치가 달라도 검증 기록의 SHA-256과 일치하는지 먼저 확인한다.

## 알림 동의·권한 실기기 시험 (10/21 추가)

[권한 연결 APK와 결과](../status/2026-10-21-notification-consent-permission.ko.md)를 따른다. 새 APK에는 연결 상태 전용 서비스가 추가됐으며 알림 본문 수집은 없다.

1. USB 연결·개발 APK 업데이트 뒤 합성 계정으로 로그인하고 ‘수집 설정’을 연다.
2. 동의 전에는 OS 설정 이동이 비활성이다. 고지를 확인하고 명시적으로 저장한 뒤에도 OS 미허용인지 확인한다.
3. 앱을 완전히 종료/재실행한 뒤 로그인 검증과 동의 복원을 확인한다.
4. 앱의 ‘Android 알림 접근 설정’ 버튼을 누르고, **사용자가 Account Book Dev만 직접 허용**한다. 제한된 설정/회사 정책이 나오면 화면 문구를 공유하며 adb 강제 허용이나 전역 보호 해제를 하지 않는다.
5. 앱으로 돌아와 실제 OS 접근과 서비스 연결을 확인한다. 동의를 철회해도 OS 권한은 별도로 남는지 확인하고 Android 설정에서 직접 해제한다.
6. 시험 후 이 앱의 알림 접근을 끄고 USB 디버깅·일시 변경한 제조사 보안 설정을 복원한다. 다른 앱의 기존 알림 권한은 변경하지 않는다.

### 서버 동의 연결 후 추가 확인 (실기기 대기)

현재 화면은 위 로컬 저장 방식 대신 서버의 동의 상태를 조회한다. 기존 로컬 동의가 있어도 서버 동의가 없으면 ‘동의하지 않음’이다. 고지 확인 후 ‘동의하고 서버에 저장’을 누르고, 재진입 뒤 유지되는지 확인한다. 철회 후에는 ‘철회됨’을 확인한다. 서버 장애·충돌이면 완료로 표시하지 않으며 ‘동의·권한 상태 다시 확인’은 조회만 한다.

이번 변경은 JavaScript 화면/모델이므로 앞서 설치한 권한 모듈 포함 개발 APK에서 최신 Metro 코드를 불러오면 된다. 새 네이티브 모듈은 없다. 로컬 서버 재시작으로 테스트 세션이 유효하지 않으면 합성 테스트 계정으로 다시 로그인한다. 실제 계정 비밀번호를 입력하지 않는다. 아직 연결된 기기가 없어 **이 서버 연결 화면의 실제 터치는 검증 전**이다. 단순 동의 저장·철회 확인에는 금융 알림 접근을 켤 필요가 없다.

실제 알림 수집은 여전히 없으며, 다음 확인 때 사용자가 별도로 허용하지 않은 권한을 자동 변경하지 않는다. [서버 연결 결과](../status/2026-10-21-mobile-server-consent.ko.md)를 참고한다.
