# How to: PC에서 계좌·카테고리·닉네임 관리하기

이 가이드는 이미 설정된 개발 서버에서 장부 기본 화면을 확인하는 방법이다. 은행의 실제 계좌를 연결하거나 실제 돈을 이체하지 않는다. 구현 원리는 [코드 흐름 가이드](core-web-development.ko.md)에 있다.

## 준비

Node 22.15.1, pnpm 11.9.0과 설치된 의존성이 필요하다. 실제 개발용 인증 설정은 [로컬 인증 가이드](local-auth-development.ko.md)를 따른다. DB 비밀번호·키를 소스나 채팅에 복사하지 않는다. 개발 서버가 이미 실행 중이면 새 서버를 중복 실행하지 않는다.

## 1. 화면 열기

개발 API와 웹이 모두 중단된 경우, 이 작업이 있는 저장소에서 두 터미널로 각각 실행한다.

```powershell
pnpm build:packages
pnpm --filter @account-book/api build
node scripts/local-auth/start.mjs api
```

```powershell
node scripts/local-auth/start.mjs web
```

웹 출력에 표시된 HTTPS 주소로 접속한다. 현재 로컬 설정은 `https://localhost:3000/login`이며 `http` 또는 `127.0.0.1`로 임의 변경하면 origin·쿠키·callback이 어긋날 수 있다. 정상 로그인하면 `/app`의 **내 계좌**가 보인다. 비로그인 상태는 로그인 안내만 보인다.

## 2. 계좌와 카테고리 저장 확인

1. **계좌 추가**에서 이름(공백 정리 후 1~80자), 은행 계좌·현금·카드 중 종류를 고르고 추가한다. 생성 후 종류는 바꿀 수 없다.
2. 생성된 행을 확인하고 새로고침한다. 같은 행이 보이면 서버 저장 후 재조회까지 확인한 것이다. 현재 시작 잔액·거래 입력은 없으므로 새 계좌 잔액은 0원이다.
3. **카테고리** 메뉴에서 수입 또는 지출, 이름(1~50자), 정렬 순서(0~10,000 정수)를 입력한다. 작은 순서가 먼저 나온다. 수정에서는 이름과 순서를 변경한다.

**보관**은 삭제가 아니다. 기존 내역을 남기고 새 거래에서 사용하지 않게 한다. 보관 항목 포함을 켜면 다시 볼 수 있지만 현재 화면에서 복원할 수는 없다. 시험도 실제 개발 DB에 저장되므로 의미 없는 금융/개인정보를 넣지 않는다. 자동 검증은 별도 폐기용 DB를 사용한다.

## 3. 내 정보와 로그아웃 확인

**내 정보**에서 닉네임을 최대 50자로 저장한다. 비우면 닉네임 없음(null)이다. 가입 경로·역할은 읽기 전용이다. 프로필 사진 업로드와 관리자 권한 변경 기능은 없다. 저장 후 새로고침해 이름이 유지되는지 확인하고 **로그아웃**을 누른다. 다시 `/app`에 접근했을 때 로그인 안내가 보여야 한다.

## 문제 해결

| 표시/증상 | 확인할 것 |
| --- | --- |
| 로그인 확인 실패 | API·웹 실행, 개발 인증 설정 확인. 세션 오류면 다시 로그인 |
| 목록 로딩 실패 | 새로고침으로 명시적 재조회. DB/RLS 권한을 느슨하게 바꿔 해결하지 않기 |
| 다른 화면에서 변경됨 | 입력을 확인하고 닫기 → 목록 새로고침 → 다시 편집. 프로필은 최신 정보 불러오기 |
| 저장 결과를 확인하지 못함 | 같은 열린 폼에서 입력을 유지해 재시도. 화면을 닫았다면 먼저 목록 확인 |
| 탭 복귀 후 폼이 사라짐 | 신원 재검사 중 화면·캐시를 비우는 현재 정책. 저장되지 않은 입력은 복구되지 않음 |
| 장부 잔액과 은행 잔액이 다름 | 현재 장부 계좌는 실제 은행과 연결되지 않음 |

## 자동 검사 재현

실제 사용자 DB에는 아래 검사를 실행하지 않는다. 로컬 loopback PostgreSQL에 폐기용 제어 DB `account_book_test`가 준비되어 있어야 한다. 테스트 도구는 고정된 로컬 테스트 자격증명만 허용하며 별도 `account_book_core_test`를 생성한다. 기존 같은 이름 DB가 있으면 덮어쓰지 않고 중단한다.

```powershell
$env:TEST_DATABASE_URL='postgresql://postgres:postgres@127.0.0.1:5432/account_book_test'
$env:TEST_DATABASE_DISPOSABLE='true'
pnpm --filter @account-book/e2e test:core
```

이 URI의 비밀번호는 폐기용 로컬 테스트 fixture이며 Supabase 비밀번호가 아니다. 포트 4510/4511/4512는 비어 있어야 하고 Playwright Chromium이 설치되어 있어야 한다. Next 개발 서버의 최초 컴파일을 위해 사례 제한은 120초, assertion 제한은 15초다. 이 수치는 운영 성능 목표가 아니다.

검사 후 `3 passed`와 종료 코드 0을 함께 확인한다. 실패 시 `tests/e2e/test-results/`와 `output/` 로그를 확인하되 실제 쿠키·키·개인정보는 보고서에 붙이지 않는다. 테스트 인증서·스크린샷·실행 결과는 Git에서 제외한다. `.next`를 공유하므로 전체 production build와 Playwright dev 서버를 동시에 실행하지 않는다.

이제 계좌·분류·닉네임의 저장/재조회 흐름을 확인했다. 다음 제품 기능은 [검증 기록의 후속 작업](../status/2026-09-30-core-web.ko.md)을 따른다.
