# Android 알림 수집 설정 UI 진행 기록

기준: 2026-10-21. 이전 완료 작업·로그인 문구 체크포인트 `8d22f64` 이후의 기능 단위다.

## 무엇을 사용할 수 있나

장부 화면의 **수집 설정**으로 이동하면 서버가 기억하는 기기 지정 상태를 확인한다. 상태는 ‘미지정’, ‘이 기기’, ‘다른 기기’ 3개다. 이 기기를 지정하거나 다른 기기에서 권한을 옮기거나 지정을 해제할 때에는 영향을 설명하는 확인 단계를 거친다.

**현재 금융 알림을 읽거나 자동으로 거래를 저장하지 않는다.** OS 알림 접근 권한, NotificationListenerService, 은행·문자·카카오톡 판독/업로드는 후속이다. 화면에도 ‘자동 기록 준비 중’과 이 제한을 명시했다. 실제 알림 수집 서비스 없이 작동하는 척하는 권한 스위치는 넣지 않았다.

## 작업 규모와 파일

사전 예상 약 15개에서 테스트 분리·화면 방향 기록·상태 문서를 포함해 21개 파일로 정리했다. 서버/DB/계약 정책 변경, 새 의존성, 새 영구 저장소는 없다. 자동 생성된 `apps/web/next-env.d.ts`는 이번 커밋에서 제외하고 기존 변경을 보존한다.

## 저장 과정과 안전장치

1. `SessionManager.collectorState()`로 현재 서버 상태와 버전을 읽는다.
2. 사용자가 동작을 고르면 `choose(action)`은 확인 내용만 만들고 아직 저장하지 않는다.
3. 확인 버튼의 `confirm()`이 그때 읽은 `expectedVersion`을 보내 다른 기기의 동시 변경을 감지한다. 다른 기기를 교체할 때만 `replaceExisting: true`다.
4. 저장 중에는 다시 누르거나 새로고침해도 PATCH가 추가되지 않는다.
5. 실패하면 PATCH를 반복하지 않고 GET으로 현재 상태를 읽는다. 읽기까지 실패하면 변경 버튼을 열지 않는다. GET에서 ‘이 기기’가 보여도 직전 저장의 성공 증거라고 단정하지 않는다.
6. 화면을 떠나거나 세션이 바뀌면 오래된 응답을 공개하지 않는다. 이미 서버가 처리한 변경이 취소됐다고 안내하지도 않는다.

## 실행한 검증

- API/세션 신규 11개: 구현 전 실패 → 구현 후 통과.
- 상태/안내 신규 21개: 구현 전 실패 → 구현 후 통과. 명시적 교체·취소·연타·충돌·응답 유실·재조회 실패·화면 재진입을 포함한다.
- 초안 이동 신규 1개: 기존 범용 이동이 이미 초안을 보존해 런타임 시험은 처음부터 통과했다. 새 `collector` 경로가 없어 타입 검사가 실패하는 것을 확인한 뒤 경로를 연결했다. 이 검사는 네이티브 화면 클릭 시험을 대신하지 않는다.
- 모바일 전체 **164개**: Vitest 154 + 도구 10 통과. 모바일 앱/핵심 타입 검사와 Android JavaScript/Hermes 번들 생성 통과. 새 APK 제작·설치 결과는 아니다.
- 전체 **2,197개**: legacy 208 + 공용 계약 176 + DB 단위 19 + 모바일 164 + API 320 + 웹 1,219 + E2E 사전 검사 91. 전체 린트·타입·테스트 종료 0.
- PC Playwright: 합성 계정 로그인, 기존 수입/지출 각 1건, 새로고침 후 각 1건 유지, 로그아웃 후 거래 숨김, 로그인 링크 이동, 페이지 오류 0. 실제 로컬 HTTPS BFF/NestJS/폐기용 DB를 사용했다.
- PC 검사의 첫 로그아웃 대기는 잘못된 자동 이동 기대 때문에 시간 초과됐다. 구현은 같은 URL에서 화면을 잠그고 로그아웃 안내/로그인 링크를 표시한다. 소스와 실제 화면을 대조해 검사 조건을 바로잡았으며 PC 제품 코드는 수정하지 않았다.
- 코드 리뷰 결과와 최종 저장 정보는 아래 마무리 기록에 추가한다.

전체 DB 통합·운영 production build·원격 CI·운영 침투시험은 이번 UI 단위에서 다시 실행한 것이 아니다. 합성 자격 증명, 기기 식별자, 실제 금융 알림 원문, 키/인증서는 문서/Git에 포함하지 않는다.

## 남은 실기기 확인과 다음 순서

현재 연결된 Android 기기가 없어 새 설정 화면의 실제 표시·큰 글자·TalkBack·Back·확인 취소는 **미검증**이다. 앞선 로그인 복원 실기기 결과로 새 화면까지 통과했다고 쓰지 않는다. Impeccable의 실제 화면 검토도 이 증거가 준비돼야 마칠 수 있다. 기존 테마를 확장했으며 전역 디자인 파일의 오래된 웹 범위는 무단으로 재설계하지 않았다.

1. 다음 연결 시 기존 개발 앱/최신 번들로 새 설정 화면을 확인한다. 휴대폰 보안 설정을 지금 다시 낮출 필요는 없다.
2. 실제 알림 접근 동의/권한 화면 → Android 알림 서비스 → 검증 가능한 한 금융 알림 형식의 판독·기록·PC 반영을 별도 계획으로 진행한다.
3. 실금융 베타 전 보안/개인정보/의존성·독립 APK·OS 재부팅/최근 앱 미리보기 게이트를 닫는다.

GitHub가 체크포인트 푸시 때 기본 브랜치의 의존성 경고 **25건(치명 2·높음 6·중간 12·낮음 5)**을 알렸다. 현재 기능 브랜치 적용 여부는 재감사 전이다. 기존 개발 기록의 경고 2건과 동일 시점/범위로 합치거나 해결됐다고 주장하지 않는다.

## 마무리 기록

독립 코드 리뷰와 원격 저장 확인 진행 중. 브랜치는 `feature/bank-state-transitions`이며 main 병합·배포·운영 DB 변경은 하지 않는다.
