# 2026-09-29 프로필·계좌·카테고리 API 진행 기록

## 범위와 결과

`feature/bank-state-transitions`, 기준 HEAD `10ec214805d5b5fb9cb2ad7a8aceea43b2bd6ebe` 위의 미커밋 작업이다. 기존 인증·DB 변경에 의존하며 그 변경을 보존했다. 이번에 NestJS + Fastify의 프로필·계좌·카테고리 10개 경로와 실제 SQL repository를 구현했다. 새 migration·원격 금융 시험 데이터·Git 커밋/푸시·배포는 없다.

- 프로필: 본인 조회 및 닉네임 수정. 역할·가입 경로·탈퇴·이미지 쓰기는 거부.
- 계좌·카테고리: 목록, 생성, 수정, 보관. 사용자 격리·엄격한 입력·version 충돌 검사.
- 생성: 요청 키 정규화, 사용자/작업별 잠금, 최초 응답 재사용, 행과 멱등 기록의 원자 저장.
- 저장 경계: 기존 풀 재사용, SET LOCAL 본인 문맥, 강제 RLS, 시간 제한, 실패 rollback·연결 폐기.
- 잔액: 실제 원장 합계, 삭제 제외, 이체·시작 잔액 방향 및 안전 정수 범위 검사.

상세 설명은 [초급 개발자용 API 흐름](../guides/core-api-development.ko.md), [설계](../superpowers/specs/2026-09-29-core-api-design.md), [파일별 계획](../superpowers/plans/2026-09-29-core-api.md)에 있다.

## 확인한 디자인

[사용자 제공 PC 참조](https://bass-spider-28476196.figma.site/transactions)를 별도 Playwright 브라우저 1440×1000으로 확인했다. 흰색 헤더·카드, 옅은 회색 배경, 가로 탭, 청록색 선택/버튼, 표와 필터 중심 구조다. 원본의 러시아어 창고/SKU/수량 기능은 가계부의 계좌·분류·금액으로 맞춘다.

사용자 지정 레퍼런스를 우선하고 Impeccable 기준으로 대비·정렬·로딩·오류·키보드 사용을 함께 확인할 계획이다. 현재 로그인 CSS는 바꾸지 않았다. 장부 화면용 디자인 기준을 캡처한 것이며 화면 구현 완료가 아니다. 증거 이미지는 Git 제외 `output/playwright/transactions-reference.png`다.

## 테스트와 실제 연결 증거

- 계약 테스트 15개를 먼저 실패시키고 구현한 후 통과했다.
- HTTP 경로 24개 검사를 미구현 상태에서 실패시킨 후 실제 Nest/Fastify·ES256 Guard에서 통과했다. repository는 이 계층에서만 대역이다.
- 실제 SQL 검사는 폐기용 PostgreSQL 17.11의 별도 최소 권한 로그인으로 수행했다. 새 core API 12개를 포함한 DB suite 205개 통과. 모듈 미구현 RED 이후 저장소를 구현했다.
- 일반 전체 `pnpm test` 1,244개 통과 후 리뷰 권고의 transaction lifecycle 테스트 3개를 추가했다. 추가 3개를 포함한 최종 전체 검증은 아래 마감 기록에서 확인한다.
- `pnpm lint`, `pnpm typecheck`, `pnpm build` 통과. 이번 빌드 결과를 이전 날짜의 빌드 경고 기록과 구분한다.
- 로컬 API의 정확한 프로세스를 확인하여 최신 빌드로 재시작했다. 다른 Node 프로세스·웹 서버는 종료하지 않았다.
- 실제 개발 Supabase의 기존 활성 회원을 메모리에서만 식별하여 로컬 Nest의 GET profile/accounts/categories를 검사했다. 인증 성공 200, 비인증 401, 재사용 401, 응답 계약, no-store 등 18개 검사 통과. 프로필·계좌·금융 기록 수정은 0건이고 정상 인증의 JWT replay 기록 3건만 생겼다.
- 관리자 연결은 위 검사의 사용자 식별 SELECT만 READ ONLY transaction에서 실행한 뒤 rollback·종료했다. 실제 API 데이터 조회는 `app_api` 런타임 연결을 사용했다. 키·URI·사용자 행은 로그나 문서에 출력하지 않았다.

## 독립 코드 리뷰와 판정

새 리뷰어가 코드를 읽고 Critical/Important 없음으로 판정했다. Minor 권고는 COMMIT 실패·rollback 실패·정상 연결 반환의 회귀 테스트 부족이었다. 기존 구현을 확인한 뒤 세 경우의 테스트를 추가했으며 기능 코드는 변경하지 않았다. 이미 올바른 동작에 검증을 추가한 것이므로 새 버그의 RED→GREEN 수정으로 부르지 않는다.

| --- | --- |

## 다음 단계와 제한

1. 새 API용 Next.js BFF route: 세션·CSRF·요청별 scope·fresh JWT·안전한 오류 변환.
2. 사용자 참조 디자인의 PC 장부 셸과 프로필/계좌/분류 화면: TSX, ky, React Query. 로딩·빈 목록·권한 만료·409·재시도까지 포함.
3. 거래·이체 저장 API와 분류·상세 화면, 이후 은행 연결·수집 상태 처리 및 별도 모바일 앱.

현재 `/app` 장부는 미구현이다. 실제 소셜 로그인, 전체 가입 여정, 운영 감사·침투 테스트, 실제 은행 조회, 모바일 실기기 테스트는 이번 검증에 포함하지 않았다. 테이블과 API 구현만으로 실제 금융 베타 공개가 가능하다고 판단하지 않는다.

## 최종 마감 검증

리뷰 테스트 추가 후 `pnpm test` **1,247개**(legacy205 + contracts89 + database19 + API205 + web643 + E2E preflight86), `pnpm typecheck`, `pnpm lint`, `git diff --check`가 통과했다. 실제 DB suite **205개**는 별도이며 위 일반 테스트 합계에 포함되지 않는다. E2E preflight는 실제 브라우저 사용자 여정 실행이 아니다. 웹/API 빌드도 통과했으며 그 이후 기능 코드 변경은 없고 테스트·문서만 추가했다.

Notion 02 인증 및 12 금융 원장 카드의 본문·현재 구현·다음 액션을 갱신하고 재조회로 확인했다. 카드 전체는 “진행 중 / 부분 구현·운영 미검증”을 유지한다. 개발 규모 분모가 없으므로 임의 진행률은 적지 않았다.

검사용 PostgreSQL 프로세스와 이번 Playwright 세션은 종료했고, 기존 HTTPS 웹 3000과 최신 Nest API 3001은 유지했다. 브라우저 진단 산출물은 Git 제외 output에 보존했다. 외부 비밀 설정은 Git/OneDrive 밖 기존 사용자 전용 경로를 재사용했으며 신규 비밀값을 소스에 저장하지 않았다.
