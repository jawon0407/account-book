## 빌드 환경 기록

기존 짧은 경로 빌드 복사본 `C:/Users/PC/a3`에 허용 목록 소스와 고정 의존성만 동기화했다. 환경 파일·실제 키·DB 자료는 복사하지 않았다. Windows 클라우드 연결 파일 때문에 Gradle이 `not a regular file`로 중단되어, 복사본의 reparse-backed 일반 파일23,669개만 같은 해시의 일반 파일로 바꿨다. 실제 링크·원본 저장소·공용 패키지 캐시는 변경하지 않았다.

다음 빌드에서는 패키지 경로 길이가 기본60자로 돌아간 탓에 기존 C++ Ninja 긴 경로 오류가 재현됐다. 설치 도구의 `optimisticRepeatInstall`이 설정만 바꾼 설치를 생략하는 것을 도구 소스에서 확인했다. 빌드 복사본에만 `.p32`, `--config.virtual-store-dir-max-length=32`, `--config.optimistic-repeat-install=false`, `--package-import-method copy`를 적용했다. 새 폴더의 클라우드 연결 파일0개와 실제 설정32자를 확인한 뒤 2분51초에 빌드가 통과했다. 기존 `.p`는 보존했다.

## 최초 시작 실패 관찰 (수정 전 이력)

합성 계정 로그인·목록 조회·대표 기기 지정 PATCH200은 정상이다. 기존 OS 접근도 허용된 상태였으며 시험 중 adb로 권한을 변경하지 않았다. 해당 앱의 알림 서비스가 실행 중임을 서비스 메타데이터로 확인했다. 시작 확인을 두 번 눌렀지만 두 번 모두 오류 안내로 돌아왔으며, 그 시점에 새로운 collector/consent 서버 조회는 기록되지 않았다.

이때는 `beginCapture`가 팝업 직후 `hasWindowFocus()`를 검사하는 타이밍을 가설로 남겼다. 후속 진단에서는 `connected=true`, `focused=false`, `ticket=-1`이 같은 시작 시도에서 확인돼 팝업의 입력 초점과 앱 활성 상태를 혼동한 것이 원인으로 확정됐다. 실제 금융 본문·식별자·키·오류 원문은 진단하지 않았다.

## 시작 오류 수정과 재검증 근거

- `NotificationAccessModule.kt`: 메인 큐에서 현재 Activity의 존재/종료 여부와 AndroidX `Lifecycle.State.RESUMED`를 검사한다. 팝업이 입력 초점을 가져갔다는 이유만으로 시작을 거절하지 않는다.
- `CaptureEngine.kt`: 명시적 시작 시 위 활성 상태를 같은 동기화 구간에서 적용하고 이전 허용을 폐기한다. 연결·세대·일회용 확인 번호·5초 만료·백그라운드 중지 조건은 유지한다.
- Android 공식 문서도 [입력 초점과 Activity 생명주기를 구분](https://developer.android.com/reference/android/app/Activity#onWindowFocusChanged(boolean))한다. RESUMED가 멀티윈도 등에서 입력 초점을 독점한다는 뜻은 아니다.
- 회귀 시험은 기존 동작에서 `An explicitly confirmed start in a resumed Activity must be allowed` 실패 후 수정으로 통과했다. pause/연결 끊김 거절 및 재연결·전경 복귀만으로 자동 재시작하지 않는 경우도 검사한다.
- 최종 전체 자동 검사: legacy208, contracts197, database19, web1225, API333, mobile309 및 도구14, e2e-preflight91 통과. 모바일 타입 검사와 Kotlin/JVM 검사도 통과했다. 임시 진단 코드는 제거했다.
- 검사 기록 도구를 통해 재실행할 때 Git Bash가 `Git/mingw64/bin/git.exe`를 우선 선택하여 기존 보안 훅 시험1건의 셸 경로 추론이 실패했다. 일반 PowerShell의 해당 시험은 통과했고, 검증용 래퍼의 PATH를 기존 `Git/cmd` 우선으로 정리한 뒤 전체 검사·모바일 타입·Kotlin/JVM 검사를 다시 실행해 종료0을 확인했다. 제품이나 시험 조건은 바꾸지 않았다.
- 독립 정적 리뷰: Critical0/Important0/Minor0. 실기기 Alert→Activity→브리지 경로는 리뷰만으로 판정하지 않고 위 양성 대조로 확인했다. 전체 앱 보안감사 재실행을 뜻하지 않는다.
- 최종 APK: `output/android-capture-device-2026-10-30/account-book-synthetic-start-fixed-debug.apk`, SHA-256 `9933b554fbb82e2a8406c3405170a74ce3c6d46bc0bc3245037f220f6caff4c7`. 서명, debug 합성전용=true, 원본/빌드 복사본 수정 Kotlin 해시 일치 및 업데이트 설치를 확인했다.
- debug APK와 release 모듈 Kotlin 컴파일은 20초/484개 작업으로 성공했다. Windows 긴 경로 제약 때문에 변경 없는 기존 arm64 C++ 산출물을 재사용했다. **clean 전체 C++ 재빌드 통과가 아니며**, 새 네이티브 의존성은 추가하지 않았다.
- UI 자동 조작 중 한 번 전면 확인이 실패해 사용자 앱 복귀 확인 후 재개했다. 도구의 입력 초점 확인 실패만으로 앱이 실제 pause됐다고 판정하지 않는다.

OS 설정으로 이동하면 전경 이탈만으로도 중지된다. 따라서 설정 왕복 시험만으로 네이티브 연결 해제 경로를 독립 검증했다고 주장하지 않는다. 실제 은행 포맷, 문자/카카오톡 지원, 백그라운드 상시 수집, 장부 저장과 PC 동기화는 이번 완료 범위가 아니다.

**시작 오류 수정 및 합성 판독·중지·화면 이탈·OS 재허용 시 자동 재시작 방지 검증과 최종 권한 정리를 완료했다.** 서버 동의와 기기 지정은 해제됐고, 사용자 해제 후 Android 접근false 및 앱 중지를 확인했다. 알림 본문은 조회하지 않고 해당 앱의 권한 여부만 점검했다.
