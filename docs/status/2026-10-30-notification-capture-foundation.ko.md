# 알림 시작·중지와 판독 기반 — 2026-10-30

## 현재 구현 범위

이번 작업은 **설정 화면이 열린 동안의 판독 미리보기**다. 앱을 닫아도 계속 기록하는 완성형 자동 가계부가 아니다. 대표 기기 지정과 동의/OS 접근은 기존처럼 독립적이며, 별도 ‘판독 시작’ 확인을 해야 읽는다.

1. 모바일이 현재 로그인·동의·대표 기기·Android 접근 상태를 확인한다.
2. Android에서 서버 확인을 시작하기 전에 최대 5초의 판독 허용 시각을 고정한다. 늦은 응답이나 같은 응답의 재사용으로 시간을 연장하지 못한다.
3. KB의 검증된 마스킹 계좌 입출금 형식에서 금액·방향·거래 상대·계좌 단서·본문 시각을 추출한다. 계좌 단서는 소유권 증명이 아니며 연도·시간대도 확정하지 않는다.
4. 최신 추출 결과만 메모리에 표시한다. 원문/결과를 파일·로그·서버·거래 DB에 저장하지 않는다.
5. 화면 이탈·백그라운드·로그아웃·권한/기기 변경·연결 실패 때 중지한다. 다시 시작하려면 사용자의 명시적 선택이 필요하다.

다른 금융 앱·문자·카카오톡 판독, 거래 저장, 중복 거래 통합, 지속 백그라운드 수집은 아직 구현하지 않았다. 고정 은행 선택 목록을 도입한 것이 아니라 최초 검증된 형식만 지원하는 단계다. 기존 권한 허용만으로 실제 금융 알림을 자동 판독하지 않는다.

## 이번 보완

| 문제 | 수정 | 확인 방식 |
|---|---|---|
| 브리지 지연이 허용 만료를 늦춤 | Android 내부에서 서버 조회 전 만료 고정, 일회용 검증 번호 | 지연 시계 실패 재현 → 통과 |
| Android 7에 없는 java.time 참조 | 연도 미확정 날짜 범위 검증으로 교체 | 해당 클래스 없는 JVM 모델 실패 재현 → 통과 |
| 2초 간격의 API 2회 조회가 공유 한도를 소진 | 완료 후 3초 간격, 60초 구간 최대 42회 | 기존 62회 실패 → 42회 이하 통과 |
| 중지 실패인데 성공으로 표시 | 중지 확인 중/확인 실패 분리, 실패 문구 보존 | 실패 재현과 지연 완료 회귀 통과 |

조회 간격을 늘렸어도 5초 만료는 늘리지 않는다. 서버가 느리면 안전하게 중지할 수 있으며, 네트워크 장애 시 계속 수집을 보장하지 않는다. 원격 철회가 즉시 전파되는 구조는 아니다. 추후 서버 저장 단계는 저장 시점에도 권한을 검증해야 한다.

## 파일과 역할

- Kotlin `CaptureEngine`: 시작 세대·만료·중복/용량·수신 경계. 본문을 읽기 전에 조건을 검사한다.
- Kotlin `CashNotificationParser`: 제한된 한 형식을 순수 함수로 판독한다. 불확실한 값은 저장하지 않고 거절한다.
- `NotificationAccessService/Module`: Android 새 알림과 앱 생명주기를 위 경계에 연결한다.
- `android-capture.ts`: Android 응답의 모양을 엄격하게 검사하며 구 APK는 시작하지 않는다.
- `collection-runtime.ts`: 로그인 범위와 비동기 응답 세대를 묶고 조회·시작·중지 상태를 관리한다.
- `collection-runtime-panel.tsx`: 명시적 안내와 시작/중지, 미리보기, 실패 안내를 담당한다.
- 기존 enrollment/앱/설정 화면: 계정·화면·동의 변경 시 중지하도록 연결한다.
- 신규 회귀 테스트, 기존 안내 문구/시험, 계획·화면 기준·이 문서를 함께 갱신한다. 서버·DB·PC 제품 코드와 의존성은 변경하지 않는다.

## 검증 결과

- 모바일 Vitest: 25파일, 309건 통과. 도구 Node 테스트: 14건 통과.
- Kotlin 순수 JVM 경계/판독 테스트 통과. Android 7 클래스 부재 모델은 실기기 시험을 대신하지 않는다.
- 모바일 타입 검사 2종, 변경 코드 ESLint, 공백 검사 통과.
- Android 모듈 compileDebugKotlin 통과. 최종 Android export: 1,418모듈, 약 4MB 번들 생성.
- 독립 코드 리뷰 최종 추가 결함 0건. 테스트/fixture는 독립 리뷰에서 요약으로만 검토했고, 본 에이전트가 전체 테스트를 읽고 실행했다. 외부 Claude Code 검토는 도구 부재로 수행하지 않았다.
- 증거 기록기의 첫 실행은 필수 Java/Gradle 인자 누락으로 실패했고 올바른 인자를 준 다음 실행은 통과했다. 기록기의 전체 결과는 이 이력을 포함해 blocked이며 전면 QA 통과로 표현하지 않는다.
- PC Playwright는 로컬 서버 연결 거부로 미완료다. 실제 계정·거래를 변경하거나 인증서 검증을 우회하지 않았다.
- 새 APK 설치·Android 실제 알림·화면 전환·TalkBack·큰 글꼴·API24 실기기 확인은 하지 않았다.

검사 증거는 Git 제외 `.gstack/qa-reports/capture-20261030/`에 보관한다. 이전 시험이나 이전 실기기 캡처를 이번 기능의 통과 근거로 사용하지 않는다.

## 전달 및 다음 단계

현재 코드 검증 후 사용자 승인 범위만 로컬 커밋한다. 원격 푸시·PR 변경·배포는 하지 않는다. 이후 별도 QA와 비공개 CSO 정적 검사의 결과를 이 문서의 후속 기록과 노션에 구분해 남긴다. CSO 상세 보안 자료는 공유 문서/Git에 전송하지 않는다.

다음은 새 APK에서 합성 알림으로 시작·중지·화면 이탈을 확인한 뒤, 최소 추출값을 서버 미분류 원장에 접수하는 계약과 저장 시 권한 검증을 구현하는 단계다. 현재 미리보기가 금융 알림 전체 자동 기록을 완료한 것은 아니다.
