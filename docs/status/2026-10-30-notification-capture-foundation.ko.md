# 알림 시작·중지와 판독 기반 — 2026-10-30

## 현재 구현 범위

이번 작업은 **설정 화면이 열린 동안의 판독 미리보기**다. 앱을 닫아도 계속 기록하는 완성형 자동 가계부가 아니다. 대표 기기 지정과 동의/OS 접근은 기존처럼 독립적이며, 별도 ‘판독 시작’ 확인을 해야 읽는다.

1. 모바일이 현재 로그인·동의·대표 기기·Android 접근 상태를 확인한다.
2. Android에서 서버 확인을 시작하기 전에 최대 5초의 판독 허용 시각을 고정한다. 늦은 응답이나 같은 응답의 재사용으로 시간을 연장하지 못한다.
3. KB의 검증된 마스킹 계좌 입출금 형식에서 금액·방향·거래 상대·계좌 단서·본문 시각을 추출한다. 계좌 단서는 소유권 증명이 아니며 연도·시간대도 확정하지 않는다.
4. 최신 추출 결과만 메모리에 표시한다. 원문/결과를 파일·로그·서버·거래 DB에 저장하지 않는다.
5. 화면 이탈·백그라운드·로그아웃·권한/기기 변경·연결 실패 때 중지한다. 다시 시작하려면 사용자의 명시적 선택이 필요하다.

다른 금융 앱·문자·카카오톡 판독, 거래 저장, 중복 거래 통합, 지속 백그라운드 수집은 아직 구현하지 않았다. 고정 은행 선택 목록을 도입한 것이 아니라 최초 검증된 형식만 지원하는 단계다. 기존 권한 허용만으로 실제 금융 알림을 자동 판독하지 않는다.

## 파일과 역할

- Kotlin `CaptureEngine`: 시작 세대·만료·중복/용량·수신 경계. 본문을 읽기 전에 조건을 검사한다.
- Kotlin `CashNotificationParser`: 제한된 한 형식을 순수 함수로 판독한다. 불확실한 값은 저장하지 않고 거절한다.
- `NotificationAccessService/Module`: Android 새 알림과 앱 생명주기를 위 경계에 연결한다.
- `android-capture.ts`: Android 응답의 모양을 엄격하게 검사하며 구 APK는 시작하지 않는다.
- `collection-runtime.ts`: 로그인 범위와 비동기 응답 세대를 묶고 조회·시작·중지 상태를 관리한다.
- `collection-runtime-panel.tsx`: 명시적 안내와 시작/중지, 미리보기, 실패 안내를 담당한다.
- 기존 enrollment/앱/설정 화면: 계정·화면·동의 변경 시 중지하도록 연결한다.
- 신규 회귀 테스트, 기존 안내 문구/시험, 계획·화면 기준·이 문서를 함께 갱신한다. 서버·DB·PC 제품 코드와 의존성은 변경하지 않는다.

## 실기기 후속 — 판독 시작 오류 수정

최초 합성 전용 APK에서 시작 확인 직후 같은 오류가 두 번 재현됐다. 별도 진단으로 확인창의 입력 초점과 앱의 활성 상태를 혼동한 것이 원인임을 확인했다. `NotificationAccessModule`과 `CaptureEngine`의 시작 경계만 수정하고, 실패 재현 시험을 통과시킨 뒤 새 APK를 설치했다. 권한·동의·세션·대표 기기·검증 번호·5초 만료 조건을 완화하지 않았다.

실기기에서 명시적 시작, 합성 입출금2건 판독, 승인/금액 불일치2건 비채택, 중지 후 무처리, 재시작 시 과거 알림 미조회, 화면 이탈 및 앱 복귀 후 중지를 확인했다. 동의 철회 요청200과 사용자 OS 접근 해제 후 ‘허용되지 않음·중지됨’도 확인했다. 재허용 후에도 새 합성 알림이 자동 처리되지 않았으며, 시험 종료 시 동의·대표 기기·OS 접근을 모두 해제했다. 상세 증거와 한계는 [실기기 검증 기록](2026-10-30-synthetic-notification-device-verification.ko.md)에 기록했다.

이번 수정의 독립 정적 리뷰는 추가 결함0건이다. 기존 CSO 부분 감사와 구분하며 전체 보안 재검사 완료로 보지 않는다. 실제 금융 앱 본문은 차단하는 합성 전용 시험이고, 서버 장부 저장·백그라운드 상시 수집·계정 변경 실기기 시험은 완료하지 않았다. C++ 기존 산출물을 재사용한 Kotlin 변경 빌드이므로 clean 전체 네이티브 재빌드 통과도 아니다. 변경과 기록은 로컬 작업 상태로 유지하며 커밋·푸시는 하지 않았다.
