# 2026-10-28 보안 패키지 및 CI 인증 오류 보완

## 요구사항과 범위

사용자가 보안 패키지 보완과 CI 인증 오류 해결을 승인했다. 변경 계획과 파일을 먼저 안내하고 Notion에도 진행 상황을 기록한다. 기능 추가, 운영 DB 변경, 실기기 시험, 커밋·푸시는 이번 작업에 포함하지 않는다.

## 착수 시 확인한 원인

- GitHub CI 실행 `39549762106` / `39549757995`에서 DB 검사 뒤 인증 브라우저 검사 3건이 실패했다. 웹/모바일 세션을 구분하는 `auth_sessions.client_channel` 컬럼이 E2E 준비 DB에 없었다.
- 준비 스크립트가 2026-07 인증 migration 4개만 적용하고, 이미 저장소에 있는 2026-10 native session migration을 누락했다. 운영 인증 로직을 완화할 문제가 아니다.
- 이전 점검의 잠금파일 감사: 전체 30건(critical 2/high 8/moderate 13/low 7), production 15건(critical 2/high 3/moderate 4/low 6). 새 검사 결과와 별도로 비교한다.
- GitHub Dependabot 40건은 기본 브랜치·서로 다른 manifest 기준이므로 로컬 audit 수와 합산하지 않는다.

## 작업 계획

1. 현재 메이저를 유지해 Next, Zod, Fastify, Vitest 및 취약 전이 패키지를 공식 수정 버전으로 올린다.
2. 수정 버전 고정 정책을 먼저 실패시키고 설치 뒤 통과하는지 확인한다.
3. 격리된 실제 PostgreSQL에서 누락 컬럼 문제를 재현한 후 기존 migration을 준비 목록에 추가한다.
4. 전체 코드 검사·테스트·빌드·인증 커버리지·DB 검사·Playwright를 실행한다.
5. 별도 리뷰 및 Notion 결과 기록. 원격 CI는 이후 커밋·푸시 뒤 확인할 수 있다.

### 문자열 길이 호환 보완

통합 테스트에서 Zod의 문자열 길이가 UTF-16 단위에서 Unicode 코드 포인트 기준으로 달라진 것을 확인했다. 이모지 6개는 JS 길이가 12지만 코드 포인트 수는 6이다. 변경을 그대로 두면 이전 입력 계약으로 허용된 비밀번호가 로그인 단계에서 거부될 수 있었다.

공용 `utf16Length` 검사기로 기존 비밀번호·계좌명·카테고리명·닉네임·이미지 키·거래 상대명·메모의 제한을 유지했다. 비밀번호 값은 trim하거나 정규화하지 않는다. ASCII로 제한되는 이메일·커서·시간대는 영향을 받지 않는다. 경계값 11건을 추가해 기존 거래 테스트와 함께 실패 12건을 먼저 재현했고, 수정 후 계약 전체 197건이 통과했다.

규모는 최초 13개 → Expo 호환성 테스트 추가 14개 → 문자열 계약 보완 포함 21개 파일이 됐다. 기존 모바일 동의 작업 파일은 이 수에 포함하지 않는다.

### CI 인증 DB 복구

준비기 목록 마지막에 기존 `20261016040532_native_session_channel.sql`을 추가했다. 새 SQL이나 운영 DB 변경은 없다. 웹 세션의 기본 채널, Android 설치 UUID 제약, BFF 조회·저장, 다른 역할의 조회 거부를 실제 PostgreSQL에서 확인했다.

새 DB 테스트는 migration 파일 자체만 검사하지 않고 **CI가 호출하는 준비기**를 실행한다. 따라서 준비 목록에서 이 migration을 빼면 다시 실패한다. 일회용 URL·DB 이름·postgres 관리자 검증은 그대로다.

## 판단 및 남겨 둔 범위

1. 커밋·푸시는 요청 범위에 없어 로컬 변경으로 유지한다. GitHub CI는 후속 푸시 후 다시 확인해야 한다.
2. `deepmerge@4.3.1`은 공식 수정판이 없어 유지한다. Expo의 앱 설정·플러그인 속성 병합 경로에서 발견됐으며, 신뢰하지 않는 설정/플러그인을 실행하지 않아야 한다. 경고를 무시 목록에 넣지 않았다.
3. Expo CLI 내부 Zod만 v4로 지정했다. 실제 설치된 소비 코드와 앱 빌드는 검증 대상이지만, 설치·활성화하지 않은 외부 `expo-mcp`/`@expo/mcp-tunnel` 등록은 미검증이다. 해당 선택 기능을 켤 때는 추가 호환 검사가 필요하다.
4. 입력 길이를 새 라이브러리 기본값에 맞춰 바꾸지 않고 기존 UTF-16 계약으로 유지했다. 대가는 공용 검사기/계약 파일 추가이며 기존 사용자 로그인 호환성을 우선했다.
5. 이전 모바일 동의 구현 및 자동 생성 `next-env.d.ts` 변경은 보존했다. 이번 리뷰가 이전 대형 기능 브랜치 전체를 다시 감사한 것은 아니다. 이전 Minor 2건·최신 동의 실기기 확인은 별도 후속 과제다.
6. 운영 DB·실제 계정·실기기를 수정/검증한 것으로 표시하지 않는다. 모든 DB 검증은 이번 작업이 새로 만든 loopback 전용 PostgreSQL에서 합성 데이터로 수행한다.
