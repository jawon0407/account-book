# Android 세션 복원 실기기 검증

## 요청과 범위

테스트 계정으로 휴대폰 앱 재실행, 통신 끊김/복귀, 로그아웃 후 재시작을 실제 화면에서 검증한다. 이전 [세션 복원 구현 기록](2026-10-20-android-session-restore.ko.md)의 메모리 저장소 시험을 실기기 증거로 대신하지 않는다.

사전 작업 계획을 사용자에게 공유했다. 제품 변경 없이 시작하며 예상 변경은 이 결과 문서와 `docs/guides/android-device-testing.ko.md` 2파일, Notion 07 진행 기록이다. 결함이 발견되면 원인·추가 변경 파일을 먼저 보고하고 회귀 시험으로 보완한다. 기존 미커밋 작업·계정·서버·DB를 초기화하지 않는다.

## 검증 순서와 완료 증거

| 순서 | 작업 | 통과 증거 |
| --- | --- | --- |
| 1 | 승인된 휴대폰 1대, 기존 개발 앱·Metro·HTTPS 서버 확인 | adb 승인 상태, 앱 foreground, TLS 검증·서버 응답 |
| 2 | 합성 계정 로그인 후 앱 프로세스 완전 종료/재실행 | 새 프로세스에서 비밀번호 재입력 없이 서버 확인 후 같은 합성 기록 조회 |
| 3 | 이 앱의 테스트 API 연결만 끊고 앱 복귀/재검증 | 장부가 가려지고 연결 실패·재연결 안내. 로그인 폼으로 불필요하게 초기화되지 않음 |
| 4 | 같은 테스트 API 연결 복원 후 다시 연결 | 비밀번호 없이 같은 기록 복구, 신규 거래·중복 생성 없음 |
| 5 | 화면의 로그아웃 후 프로세스 종료/재실행 | 로그인 화면 유지, 이전 계정 장부 미노출 |

개발 앱의 화면 코드 연결(USB 8081)은 유지하고 API 연결(USB 3000)만 일시 해제해 통신 실패를 재현한다. 휴대폰 Wi-Fi·모바일 데이터·비행기 모드·방화벽을 바꾸지 않는다. 실제 전체 무선망 단절 시험과 구분한다. 작업 실패 시에도 테스트 API 역방향 연결을 복원한다.

앱 프로세스 종료는 Account Book Dev에만 적용하며 앱 데이터/보안 저장소를 지우지 않는다. 필요 시 설치 APK/Metro 소스 경로를 확인하되 재설치나 `pm clear`로 복원 시험을 우회하지 않는다. 화면 근거는 해당 앱만 수집하고 실제 계정·기기 식별자·토큰·비밀번호를 문서나 Notion에 올리지 않는다. 새 APK 생성·운영 Supabase·금융 알림·배포·커밋/푸시는 범위 밖이다.

## 최종 확인 결과 — 2026-10-21

요청한 핵심 시나리오 **3/3 통과**: 앱 완전 종료 후 복원, API 통신 끊김/복구, 로그아웃 후 재시작이다. 아래 체크는 이 범위만 의미하며 휴대폰 OS 전체 재부팅이나 출시 검증 완료를 뜻하지 않는다.

- [x] 승인된 Android 16 기기 1대와 기존 개발 APK·최신 작업 트리 Metro 확인.
- [x] 실제 Next BFF·NestJS·합성 인증 제공자·기존 폐기용 PostgreSQL 재사용. TLS 독립 검증 `authorized=true`, HTTPS 로그인 페이지 200.
- [x] 앱 재실행 후 안전한 세션 복원 — 프로세스 종료를 확인한 뒤 다른 PID로 시작. 비밀번호 재입력 없이 서버 세션 확인 200 후 기존 합성 입출금 각 1건 표시.
- [x] API 통신 단절 중 장부 숨김 — USB 3000만 해제한 뒤 앱을 백그라운드로 보냈다가 복귀. 연결 실패 안내·다시 연결·이 기기에서 로그아웃이 표시되고 기존 거래는 보이지 않음.
- [x] 통신 복구 후 같은 계정 기록 복원 — USB 3000 복원 후 다시 연결. 추가 로그인 없이 같은 지출 20,000원·수입 50,000원이 각 1건 표시됨.
- [x] 로그아웃 후 재시작 시 이전 장부 미노출 — 서버 로그아웃 200 뒤 앱 프로세스를 종료/재실행. 빈 이메일·비밀번호 입력란의 로그인 화면 유지, 이전 장부 없음.
- [x] 시험 종료 시 API 3000·Metro 8081 USB 역방향 연결 복원 확인.
- [x] PC Playwright 재확인 — 같은 합성 기록 각 1건, 새로고침 후에도 각 1건, 로그아웃 후 장부 숨김, 페이지 오류 0.

모바일 이미지는 Git 제외 `output/android-device-2026-10-20/` 아래에 있다. 서버 증거는 같은 폴더의 `resume-1021-web.log`, 실행 환경은 `resume-1021.ts`에 있다. 이미지·비밀키·토큰·기기 식별자는 Notion에 올리지 않고 결과 요약만 전송한다.

`createRuntime()`은 실제 Expo SecureStore 어댑터를 사용한다. 앱 데이터 삭제·재설치·보안 저장소 초기화 없이 프로세스만 종료했다. 따라서 이번 복원은 이전 메모리 저장소 대역 시험과 구분되는 실기기 결과다. 저장소의 비밀값을 직접 추출한 시험이나 암호화 구현 감사는 아니다.

개발 클라이언트는 프로세스 재시작 때 Metro 연결 화면을 먼저 보여 줬다. 같은 로컬 Metro를 선택했으며 계정 비밀번호를 다시 입력하지 않았다. 독립 실행 APK의 자동 진입 UX까지 검증한 것은 아니다.

## 중단·재개와 시험 환경 문제

- 10/20에는 호스트 adb 정상 조회 결과 기기 0대였고 사용자의 외출 요청으로 중단했다. sandbox 안의 adb 데몬 실패를 기기 없음의 증거로 쓰지는 않았다.
- 10/21 재개 때 기기 1대가 연결돼 있었지만 PC 테스트 서버는 종료 상태였다. 살아 있는 서버를 중복 시작하지 않고 종료를 확인한 뒤 기존 폐기용 DB를 초기화 없이 재사용했다. 새 실행의 세션 키가 달라 최초 합성 로그인을 다시 한 뒤 재실행 시험을 수행했다.
- Metro가 IPv6 loopback에만 열려 USB IPv4 경로에서 접근되지 않았다. 해당 실행에만 IPv4 우선 옵션을 적용해 복구했다. 전역 네트워크/보안 설정은 바꾸지 않았다.
- 로그아웃 후 재실행 중 화면 전환에서 foreground 보호 검사가 한 차례 멈췄다. 보호를 해제하거나 임의 입력하지 않고 다시 실제 화면을 조회해 최종 로그인 화면을 확인했다.
- PC 기본 브라우저는 테스트 CA를 신뢰하지 않았고, 격리 Chromium 실행 파일도 없었다. 추가 설치나 전역 인증서 변경 없이 기존 Edge를 Playwright로 실행하고 독립 검증한 테스트 공개키 지문 한 개만 한정 허용했다. 첫 도구 호출의 페이지 핸들이 다음 호출에 유지되지 않아 시험을 한 호출 안에서 실행하고 종료 시 브라우저를 닫았다.

## 변경 범위·남은 점검

제품 코드·DB 스키마·APK 변경 없이 문서 4개(이 기록, 실기기 안내, 기존 세션 복원 기록, 모바일 README)와 Git 제외 실행/화면 증거만 갱신했다. 완료 후 서로 모순되는 설명을 남기지 않기 위해 사전 예상 2개에서 문서 2개를 추가했고 사용자에게 먼저 알렸다. 기존 미커밋 작업은 보존했다. 커밋·푸시·배포·운영 Supabase 변경은 하지 않았다.

이번에 전체 단위 시험·전체 DB 통합·production build·원격 CI를 다시 돌린 것은 아니다. 10/20의 2,164개 자동 시험 결과를 오늘 새로 실행한 결과로 표시하지 않는다.

후속 점검은 휴대폰 OS 재부팅, 최근 앱 미리보기·화면 잠금, 저장 도중 통신 실패, 긴 세션 만료/회전, 접근성이다. 이번의 **세션 검증 중 API 연결 실패**와 **거래 저장 중 실패**는 다른 시험이다. 알림 접근/자동 수집·소셜 실인증·실금융 베타는 아직 완료되지 않았다.

가벼운 안내 문구 불일치도 발견했다. `apps/mobile/src/ui/login-screen.tsx`의 ‘완전히 다시 실행하면 재로그인 필요’ 문장은 새 복원 동작과 다르다. 기능 실패가 아닌 후속 문구 수정 항목으로 남겼으며 이번에는 제품 코드를 변경하지 않았다.

10/21 후속 사용자 요청으로 위 문구를 ‘앱을 다시 열면 로그인 상태를 안전하게 확인해요. 세션이 만료되면 다시 로그인해 주세요.’로 수정했다. 앞선 실기기 시험과는 별도 변경이며 인증 로직은 그대로다. 이전 완료 작업까지 함께 커밋·푸시하는 범위를 사용자에게 확인받았다.

검증 종료 후 USB를 분리하거나 USB 디버깅을 꺼도 된다. 사용자가 일시 해제했던 보안 설정은 사용자가 복원하며 이 작업에서 임의 변경하지 않았다.

스킬 적용: verification-before-completion의 실제 증거 대조, Playwright의 PC 교차 확인, Notion spec-to-implementation의 완료/미검증 구분. 전체 보안 감사 완료를 뜻하지 않는다.
