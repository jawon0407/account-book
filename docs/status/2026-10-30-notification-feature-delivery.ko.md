# 알림 판독 기능별 작업 정리 — 2026-10-30

## 이번 전송 범위

사용자가 시작 오류 수정과 실기기 검증을 확인한 뒤 커밋·푸시 및 기능별 기록을 요청했다. 기존 `feature/bank-state-transitions` 브랜치에 전송하며 PR 생성·병합·서비스 배포는 하지 않는다. 과거 계획과 시험 기록의 ‘커밋·푸시 없음’은 당시 상태이며, 이번 후속 요청부터 전송이 승인됐다.

푸시 전 원격을 조회했을 때 로컬에만 있던 커밋은 다음 2개다. 이 두 커밋과 이번 합성 시험/시작 오류 수정 커밋을 함께 전송한다.

- `c9909a3` — 전경 알림 판독 시작·중지와 미리보기 기반.
- `fa71482` — 판독 기반 검증 결과 및 남은 작업 기록.

## 기능별 변경 사항

| 기능 | 사용자가 얻는 동작 | 주요 구현 위치 |
| --- | --- | --- |
| 명시적 판독 시작·중지 | 동의·대표 기기·Android 접근을 준비한 뒤 사용자가 시작한다. 설정 화면에서만 판독하며 중지하면 미리보기를 비운다. | `collection-runtime.ts`, `collection-runtime-panel.tsx`, `CaptureEngine.kt` |
| 금융 알림 판독 미리보기 | 지원하는 KB 형식에서 입출금 방향·금액·거래 상대·마스킹 계좌 힌트·본문 시각을 추출한다. 단순 승인이나 금액 불일치는 거래로 확정하지 않는다. | `CashNotificationParser.kt`, `NotificationAccessService.kt` |

| 시작 확인창 직후 오류 수정 | 확인 팝업이 입력 초점을 가지고 있어도 실제 앱이 활성 상태이면 시작 검증을 진행한다. 앱이 일시정지·종료됐거나 리스너 연결이 없으면 허용하지 않는다. | `NotificationAccessModule.kt`, `CaptureEngine.kt` |
| 중지·재허용 안전 경계 | 화면 이탈·세션 변경·동의/기기 상태 변경 시 중지한다. 이전 검증 응답이나 OS 권한 재허용만으로 자동 재시작하지 않는다. | `collection-runtime.ts`, `collector-enrollment.ts`, `CaptureBehaviorTest.kt` |

### 합성 모드가 실제 금융 알림을 읽지 않는 이유

`accountBookSyntheticCapture=true`를 명시한 debug 빌드만 Android shell의 `account-book-test-` 태그 알림을 받는다. 실제 금융 앱은 본문 접근 전에 거절한다. 일반 debug와 release는 합성 모드를 기본 허용하지 않으며, release는 항상 false다. 앱 화면·JavaScript·저장된 설정으로 이 값을 바꾸지 못한다.

### 시작 오류의 원인과 수정

확인 팝업이 열린 동안 `hasWindowFocus()`가 false였고, 이를 백그라운드로 해석해 서버 조회 전에 시작을 거절했다. 메인 큐에서 현재 Activity의 실제 `RESUMED` 상태를 확인하도록 바꿨다. 동의·기기·세션·일회용 검증 번호·5초 만료는 유지하며 임의 대기시간으로 오류를 숨기지 않았다. 임시 진단 코드는 제거했다.

## 검증 결과

- 실패 재현 후 수정: 활성 Activity 시작 허용, 비활성/연결 끊김 거절, 재연결만으로 재시작하지 않는 JVM 회귀 시험.
- 전체 자동 검사: legacy208, contracts197, database19, web1225, API333, mobile309 및 도구14, e2e-preflight91 통과. 모바일 타입 검사 및 Kotlin/JVM 검사도 통과했다.
- 실기기: 합성 입금·출금2건 정상 판독, 승인·금액 불일치2건 비채택, 중지 후 무처리, 재시작 시 과거 알림 미조회, 화면/앱 복귀와 OS 재허용 후 자동 재시작 없음 확인.
- 최종 정리: 서버 동의 철회·대표 기기 해제, 사용자 OS 접근 해제 후 실제 접근false와 앱 중지 확인.
- 독립 정적 리뷰: 추가 결함0건. 이전 CSO 결과는 모바일 알림 경로의 부분 정적 검증이며 전체 보안 승인이나 이번 코드의 실행형 보안검사 통과를 뜻하지 않는다.
- 빌드: 변경 Kotlin 컴파일 및 debug APK 생성 성공. Windows 경로 제약 때문에 변경 없는 기존 C++ 산출물을 재사용했으므로 clean 전체 네이티브 재빌드 통과는 아니다.

커밋 직전 동일 코드로 전체 자동 검사·모바일 타입·Kotlin/JVM·공백 검사를 다시 실행해 종료0을 확인했다. 원격 CI 결과는 이 로컬 검사와 구분해 전송 후 노션에 기록한다.

## 아직 구현하지 않은 기능

현재는 기기 메모리에서 판독 결과를 잠시 보여주는 기반이다. 실제 금융 앱 전체 지원, 문자·카카오톡 판독, 백그라운드 상시 수집, 서버 자동 장부 저장·자동 분류·중복 거래 연결은 이번 완료 범위가 아니다. 일반 빌드의 KB 파서가 있다는 사실을 실제 은행 앱 종단 검증 완료로 해석하면 안 된다.

다음 단계는 최소 추출값을 서버의 미분류 거래로 접수하는 계약과 저장 시 동의·대표 기기·세션 재검증이다. 이번 전송에서 PC·서버·DB 제품 코드나 DB 스키마·의존성은 추가 변경하지 않았다.

## 포함하지 않는 자료

실제 `.env`, 키·토큰·비밀번호, APK·서명 파일, 기기 식별자, 개인 금융 알림, 무필터 기기 로그 및 상세 비공개 보안 자료는 커밋하지 않는다. 합성 시험 데이터만 코드에 포함한다.
