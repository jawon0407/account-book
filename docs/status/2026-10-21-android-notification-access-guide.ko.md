# Android 알림 접근 동의·권한 안내

## 착수 전 계획 — 2026-10-21

사용자 요청은 실기기 확인을 나중으로 미루고 알림 접근 동의·권한 안내부터 개발하는 것이다. 기존 승인된 개인 알림 장부 정책을 화면에 설명하는 작은 변경이며, 별도 제품 선택을 다시 요구하지 않는다.

현재 앱에는 수집 기기 지정 UI만 있고 Android NotificationListenerService와 권한 연결은 없다. 따라서 이번에는 **안내 UI만 구현**한다. 동의를 받았다고 저장하거나 OS 설정을 열거나 알림을 수집하지 않는다. 실제 동의 수집은 고지 버전·철회·계정 격리와 네이티브 권한 확인이 준비된 뒤 연결한다.

### 범위와 파일

| 파일 | 변경 | 예상 규모 |
| --- | --- | --- |
| `apps/mobile/src/ui/notification-access-guide.tsx` | 신규. 현재 제한을 항상 표시하고 동의·권한 설명을 펼쳐 읽는 컴포넌트 | 약 120줄 |
| `apps/mobile/src/ui/collector-screen.tsx` | 기존 화면에 안내를 연결하고 오래된 다음 단계 문구 수정 | 약 5줄 |
| `apps/mobile/README.md` | 파일 역할·현재 안내와 실제 권한 기능의 차이 기록 | 약 10줄 |
| `apps/mobile/.impeccable/surfaces/apps-mobile-src-ui-collector-screen-tsx.md` | 기존 화면 방향에 안내 확장·검증 제한 추가 | 약 10줄 |
| 이 문서 | 계획·원리·검증 결과·후속 단계 | 약 80줄 |

처음 검토한 별도 안내 데이터/문구 시험 파일은 만들지 않는다. 사람을 위한 문구를 그대로 대조하는 테스트는 동작 오류를 잡지 못하며, 기존 사용자 요청대로 간단한 화면·문구 변경에 불필요한 시험을 늘리지 않는다. 서버·DB·공용 계약·의존성·앱 manifest·새 권한·라우팅은 변경하지 않는다. 기존 자동 생성 `apps/web/next-env.d.ts` 변경은 보존하고 이번 작업에서 제외한다.

### 화면 동작

1. 수집 설정의 기기 지정과 새로고침 아래에 ‘알림 접근 전 알아두세요’를 둔다.
2. 현재는 안내만 제공하며 읽기만으로 동의·권한이 저장되지 않는다는 문구는 접어도 보인다.
3. ‘동의·권한 안내 보기/접기’는 이 화면의 표시 상태만 바꾼다. 장부·기기 지정·세션·서버에는 영향을 주지 않는다.
4. 아래 설명은 **후속 자동 기록 기능의 예정 처리 기준**으로 명확히 표시한다.
   - 새 금융 알림만 처리. 과거 문자/채팅 조회 없음. 일반 대화·OTP·광고·카드 승인만으로 거래 작성 금지.
   - OS 알림 접근은 금융 전용 권한이 아니므로 앱에서 사용자가 고른 출처와 지원 형식을 선별해야 한다.
   - 다른 앱 알림을 읽는 접근 권한과 우리 앱이 안내를 띄우는 알림 표시 권한을 구분한다.
   - 동의·OS 접근·출처 선택·수집 켜기·유효한 지정 기기와 서비스 연결을 별도로 확인한다.
   - 선택하지 않아도 수기 장부 사용 가능. 중지/철회와 기존 거래 삭제는 별개다.
   - 숨겨지거나 발생하지 않은 알림은 복구를 보장하지 않으며 수기로 보완한다.

### 검증 계획

- 기존 모바일 테스트, 전체 린트, 타입 검사, Android JavaScript/Hermes 번들 생성.
- PC Playwright로 합성 계정 로그인·기록 조회·새로고침·로그아웃의 회귀 확인. PC 확인은 네이티브 UI 검증을 대체하지 않는다.
- 실기기·큰 글자·TalkBack·Back·OS 권한 상태 검증은 사용자 요청에 따라 보류. 휴대폰 연결이나 보안 설정 변경을 요구하지 않는다.
- 실제 알림 수집, 새 APK 설치, 운영 배포, 운영 DB 변경, 보안 감사 전체 통과로 확대하지 않는다.

### 공식 근거

- [Android NotificationListenerService](https://developer.android.com/reference/android/service/notification/NotificationListenerService): 시스템 알림 콜백을 받을 별도 서비스 선언과 연결 확인이 필요하다.
- [Android 알림 표시 권한](https://developer.android.com/develop/ui/compose/notifications/notification-permission): Android 13 이상 POST_NOTIFICATIONS는 우리 앱의 알림 표시에 관한 권한이다. 다른 앱의 알림 접근과 다르다.

## 실행 결과

### 구현

- 계획대로 총 5개 파일이다. 신규 안내 컴포넌트는 120줄, 기존 화면은 4줄 추가/2줄 삭제, README는 3줄 추가, 화면 설계 기록은 9줄 추가/1줄 삭제다. 나머지는 이 계획/결과 문서다.
- `NotificationAccessGuide()`는 매개변수가 없고 `useState(false)`로 설명을 접어 시작한다. 클릭 시 `expanded`만 바뀐다. 서버 요청·동의 체크박스·영구 저장·OS 설정 호출이 없으며 화면을 떠나면 펼침 값도 폐기된다.
- `Section({ title, paragraphs })`는 주제와 설명 문단만 그린다. 실제 계정·알림 원문을 받지 않는다.
- 버튼의 역할과 펼침 상태를 접근성 속성으로 알리고 최소 높이 48dp, 기존 색상·글자 크기, 상위 스크롤을 재사용했다. 고정 높이로 본문을 자르거나 새 애니메이션/이미지를 추가하지 않았다.
- Impeccable의 clarify 기준으로 현재 제한은 항상 표시하고 긴 설명만 펼치도록 나눴다. 기존 Bookify 방향과 디자인 토큰은 유지했다. 네이티브 시각 검증은 보류이므로 완성도 승인과 구분한다.

PC는 설치된 Edge의 격리된 Playwright 실행과 기존 테스트 인증서 공개키 지문에 한정해 접속했다. 전역 TLS 검증이나 휴대폰 보안 설정을 바꾸지 않았다. PC 검사는 새로운 Android 안내의 렌더링/동작 시험을 대체하지 않는다.

**미실행:** 전체 서버/웹/DB 단위 시험 재실행, DB 통합/운영 빌드/원격 CI, 네이티브 안내 화면·큰 글자·TalkBack·Back·OS 권한 검증. 이전 전체 2,197개 결과를 이번 실행 결과로 재사용하지 않는다. 실기기 보류는 사용자의 명시적 요청이며 권한을 켜거나 연결해 달라고 요구하지 않았다.

### 기록과 저장 상태

착수 전에 Notion ‘07. 현재 구현 상태·변경 이력·다음 작업’에 범위와 5파일 계획을 기록하고 결과를 후속 반영한다. 비밀번호·토큰·실제 금융 알림·기기 식별자는 전송하지 않는다. 이번 요청은 안내 구현과 기록이며 커밋·푸시·배포·운영 DB 변경은 하지 않았다. 기존 의존성 경고의 해소나 실금융 베타 승인으로 해석하지 않는다.
