## 현재 검증 증거

- 첫 전체 `pnpm test`: 1,695개 통과(기존1,637 + A4 신규58). 웹은1,017개.
- 리뷰 보완 후 최종 `pnpm test`: 1,698개 통과(legacy207 + contracts89 + database19 + API277 + web1,020 + E2E preflight86). A4 신규61개이며 실제 은행 E2E를 포함한 수치가 아니다.
- 전체 lint와6 workspace 타입 검사 통과.
- Next/Nest를 포함한 전체 프로덕션 빌드 통과. 빌드 결과를 임시 루프백 서버에서 실행해 시작·결과 페이지 HTTP200, `Cache-Control: no-store, private`, `Referrer-Policy: no-referrer`를 직접 확인했다. 확인 후 임시 서버를 종료하고 기존 로컬 HTTPS 서버를 복구했다. 개발 모드의 헤더와 배포 빌드의 헤더를 구분했다.
- PC Playwright: 실제 localhost HTTPS 경로에서 미로그인 차단 확인. 별도 브라우저에 합성 /api/me 및 은행 응답을 주입해 준비 중·확인·완료 응답502·조회 성공 복구·잘못된 복귀 URL 거부를 확인.
- 1920/1440/1080/390px 가로 넘침 없음, localStorage/sessionStorage 비어 있음. 마지막 정상 시작 화면 콘솔 오류0/경고0. 거부/실패 재현 중 의도한 HTTP401/502 기록은 별도로 존재한다.
- Impeccable 레이아웃 독립 평가+기계 검사: 기존 장부 색상/간격 재사용, 작은 페이지의 여백 중첩 방지, 결과 경로에서도 활성 메뉴 유지. CSS 신규3줄.
- DB migration 변경 없음. 실제 PostgreSQL300개는 A3 증거이며 A4에서 새로 실행한 것으로 계산하지 않는다.

## 제한과 다음 단계

공식 은행 시작은 서버 endpoint=null, PC 기본 비활성. 가상 성공·실계좌 성공을 만들지 않았다. A5는 BFF→실제 Nest→로컬 DB→가상 Callback 전체 여정과 세션/쿠키/동시성 테스트다. A6는 공식 명세·자격·키·Callback 설정 후 금융결제원 테스트다. 잔액·거래 수집·모바일·정리 worker·클라우드 은행 schema 적용은 후속이다.

GitHub 기본 브랜치의 열린 경고2건(#32/#33)은 `fast-uri` 중간 등급 경고다. GitHub가 제시한 영향 범위는 각각 `>=4.1.3,<4.1.5`, `>=4.0.0,<4.1.5`다. 현재 기능 브랜치의 lockfile/`pnpm why`는 3.1.8과 패치된4.1.5이며, 두 버전 모두 해당 두 경고 범위 밖이다. A4 신규 의존성은 없고 기존 패치 커밋4f08032를 유지했다. main에 아직 병합하지 않아 GitHub 경고가 열려 있으며 수동 해제하지 않았다. 이는 이 두 경고의 버전 대조이지 전체 의존성 무취약 보장은 아니다.

## 작업 중 판단

1. 반복 승인/새 디자인 시안은 생략하고 승인된 장부 디자인을 재사용했다. 선호가 다르면 후속 시각 조정이 필요할 수 있다.
2. 공식 endpoint를 추측하지 않고 A6까지 비활성을 유지한다. 따라서 A4만으로 은행 인증을 시작할 수는 없다.
3. Task1 회귀는 미리 작성한 Task2 RED 파일만 제외했다. Task2 이후 전체 웹1,017개와 전체1,695개를 포함해 다시 실행했다.
4. 단일 proof 쿠키를 요청별 이름으로 변경했다. 이전 완료 응답이 새 요청을 망가뜨리지 않게 한다. 비용은 잠시 여러 쿠키가 남을 수 있다는 점이며 5분 만료·기존 시작 제한·서버 결속은 유지한다.
5. 공식 URL의 client_id/redirect_uri/scope 의미 검증은 A6로 남긴다. 현재 비활성이라 공식 설정 성공을 주장하지 않는다. 추후 공급자 설정에 따라 추가 수정이 필요할 수 있다.
6. DB→Callback→브라우저 전체 가상 여정은 A5다. 이번 합성 응답 화면 검증으로 이를 대체하지 않는다. 통합 단계에서만 발견되는 결함은 아직 남을 수 있다.

## 독립 리뷰 보완과 재현

- 완료 요청 중 화면/인증 경계 종료 → 늦은 성공: 기존 캐시 재생성을 재현한 뒤 active guard로 차단했다.
- 시작 요청 중 화면 종료 → 늦은 URL: 원하지 않는 은행 페이지 이동을 재현한 뒤 동일 guard로 차단했다.
- 탭 A 완료 지연 → 탭 B 시작 → A 응답 도착: B 쿠키까지 지워지는 실패를 재현했다. 요청별 쿠키 격리 후 B 완료가 정상 진행되는 것을 검증했다.
- 세 테스트 RED→GREEN, 은행 scoped58개 통과. 중요한 지적2건의 기능적 보완이며 미룬 Minor는 없다.
- 최종 전체 검증 도중 실행 helper의 Git Bash PATH가 기존 hook 테스트의 Windows 셸 경로 추론을 바꿔1건 실패했다. 자식 PowerShell에서 Git/cmd 우선순위를 복구해 재실행했다. 보안 검사·테스트 제외나 제품 코드 우회는 하지 않았다.
- 첫 A4 푸시 명령의 로컬 `HEAD` 표기는 보안 훅이 거부했다. 정식 `refs/heads/feature/bank-state-transitions`를 양쪽에 지정해 정상 전송했다. 훅을 우회하거나 원격 이력을 덮어쓰지 않았다.

실제 변경 규모: A4는 문서 포함30개 파일, 새 제품 코드의 가장 긴 파일은67줄이다. DB migration·새 의존성·실제 은행 secret 변경은 없다. main 병합·PR 생성·배포·신규 CI 성공은 이번 완료 주장에 포함하지 않는다.
