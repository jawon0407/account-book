# 인증 보안 테스트 보완 진행 기록

## 목적과 승인

사용자는 기존 100% 기준을 유지하며 테스트를 보완한 다음 PR #12 병합, PR #13의 대상을 main으로 변경, 보안 경고 재확인 순서로 진행하는 안을 승인했다. 실행 방식은 현재 세션 순차 구현 후 마지막에 별도 에이전트가 전체 변경을 리뷰하는 방식이다.

계획: [파일별 실행 계획](../superpowers/plans/2026-09-23-auth-coverage-completion.md).

## 무엇을 검증했나

분기 커버리지는 조건문의 각 경로가 테스트 중 실행되었는지 보여 준다. 100%는 모든 취약점이 없다는 뜻이 아니다. 이번 기준의 대상은 `apps/web/vitest.config.ts`에 지정된 웹 인증 보안 모듈이며 전체 앱·은행 연동의 커버리지와 다르다.

| 영역 | 보완 내용 |
| --- | --- |
| 제공자 HTTP | 성공/실패 응답의 JSON 파싱 실패, 오류 코드 누락, 원문 숨김 |
| JWT 파서 | 잘못된 base64url 구간과 데이터 없는 응답의 오류 검사 |
| 취소·설정 | 전송 전 이미 취소된 Request, 잘못된 URL 입력 |
| 이메일 인증 | callback 안전성, 입력·시각·UUID 오류, 검증된 사용자와 토큰 불일치 |
| 개발용 IdP | 응답 형식·타입·만료·기본 fetch 처리. 실제 외부 요청 없음 |
| 세션 | 원시 제공자 오류의 고정 오류 변환, 기본 완료 시각 적용 |
| DB 경계 | 비정상 행/행 개수, 날짜 복사, 복구 단계·소비 시각, 잠금 실패 시 후속 작업 중지 |
| CI | 일반 verify 외에 웹 보안 분기 coverage 검사를 독립 필수 단계로 추가 |

DB 테스트는 공통 준비 코드, 세션 저장/회전, 인증 거래로 분리했다. 준비 코드의 FakeDatabase는 SQL 입력·실행 순서·반환값을 통제할 뿐 실제 PostgreSQL의 롤백·동시 실행을 구현하지 않는다. 이 단위 테스트로 실제 DB 동시성까지 검증했다고 주장하지 않는다.

## RED/GREEN 해석과 수정 판단

기존 동작의 누락 테스트를 추가했으므로 새 테스트가 처음부터 통과하는 경우가 있다. 이를 제품 결함을 재현한 RED라고 부르지 않는다. 이번 RED는 100%에 미달한 커버리지 검사이며, GREEN은 기준을 유지한 채 추가 테스트로 검사를 통과한 것이다.

새 DB 테스트의 초기 4개 실패는 fixture 작성 오류였다. Vitest가 배열 사례를 인자 목록으로 펼치는 문제는 객체로 감싸 해결했고, 저장소가 반환하는 Uint8Array를 Buffer와 비교하던 기대값은 반환 계약에 맞췄다. 제품 코드는 변경하지 않았다.

실행 계획의 조정: 도중 취소는 기존 테스트에 있으므로 사전 취소를 보완했다. URL 생성자 실패뿐 아니라 URL/문자열이 아닌 타입도 추가했다. 판단이 잘못됐다면 해당 입력·기대값을 재검토해야 하며 보안 검증 자체를 제외하지 않는다.

## 최종 로컬 검증과 남은 절차

최종 `pnpm verify` 종료 0: legacy 54 + contracts 66 + database 15 + API 148 + web 643 + E2E preflight 85 = **1,011개 테스트 통과**. lint·타입 검사·API/web 빌드도 모두 통과했다. 검증 코드 SHA는 `0a83f55`이며 이후 변경은 이 결과와 계획 체크리스트를 반영하는 문서뿐이다.

전체 검증 재시도 중 Windows 실행 환경의 Git 경로 순서로 pre-push 실행 테스트가 실패했다. Git Bash가 먼저 찾은 mingw64/bin/git.exe 기준으로 sh.exe 경로를 잘못 계산한 것이 원인이다. 기본 PowerShell에서는 같은 6개 테스트가 통과했고, 검증 실행 환경에서 Git/cmd를 우선하도록 한 뒤 전체 검증이 성공했다. 제품/테스트 코드를 우회하거나 검사 기준을 바꾸지 않았다. 다른 Windows 실행 환경에서는 같은 경로 문제를 재확인해야 한다.

이번 작업은 테스트·CI·문서 16개 파일, 887줄 추가·262줄 삭제(이동 포함)다. 제품 구현·의존성·DB 스키마·coverage 설정은 변경하지 않았다. 사용자 .gitignore 1줄은 이 통계와 커밋에서 제외했다.

최종 독립 리뷰: 중대·중요 문제 없음. 기존 DB 테스트 본문이 모두 보존됐고 CI 검사가 우회 조건 없이 추가됐음을 확인했다. 비차단 후속 의견 1건은 기본 시계 테스트에서 제공자 호출 도중 시간을 이동해 완료 시각·만료 경계를 더 명확히 검증하는 것이다. 현재 주입 시계 테스트가 관련 동작을 검사하므로 이번에는 기록하고 보류한다.

리뷰 범위는 이번 테스트/CI 보완이며 앞선 누적 PR 전체에 대한 신규 보안 감사가 아니다. 실 DB 롤백·동시성은 CI의 폐기용 DB 통합 검증, 실제 hosted 제공자는 출시 전 검증으로 남는다.

현재 브랜치 `pnpm audit --json`: 모든 severity 0, 종료 0. main의 Dependabot 경고 해소와는 별개다.

전체 verify 첫 실행은 기존 CI 원문 해시 검사에서 실패했다(legacy 53/54). 새 coverage 단계가 추가돼 검토 기준 해시가 바뀐 것이 원인이다. 권한·Action SHA·비밀정보·브랜치 정책을 유지한 3줄 변경을 확인한 뒤 `scripts/security/workflow-policy.test.mjs`의 기준 해시와 필수 실행 순서에 coverage 명령을 반영한다. 검사를 삭제하거나 우회하지 않는다.
