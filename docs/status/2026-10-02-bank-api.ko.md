# A3 NestJS 은행 연결 API — 진행 기록

## 범위

조회 전용 은행 연결의 저장소·서비스·HTTP 경계를 구현한다. 기존 기능 브랜치와
미커밋 인증/거래/A2 변경은 보존한다. 공식 KFTC 서버 호출, Supabase 운영 migration,
PC 은행 화면, 커밋·푸시·배포는 이번 범위가 아니다.

[설계](../superpowers/specs/2026-10-02-bank-api-design.md),
[파일별 계획](../superpowers/plans/2026-10-02-bank-api.md),
[초급 개발자용 흐름](../guides/bank-api.ko.md)을 함께 읽는다.

## 구현과 검증

- [x] Task1: DB 저장소. 6개 미구현 RED → 실제 PostgreSQL 6개 GREEN.
- [x] Task2: 암호화·claim·8초 timeout·실패 종료. 14개 RED → GREEN.
- [x] Task3 HTTP: 13개 경로/권한 미구현 RED → GREEN. 실제 Nest/Fastify와 ES256 서명 사용.
- [x] 전체 로컬 PostgreSQL 300개 통과(기존294 + 신규6).
- [x] 최종 일반1,637개(신규39)·전체 lint·6개 workspace 타입·API build 통과.
- [x] PC1440×900 로그인→비밀번호 찾기 공개 폼 이동 Playwright smoke. 콘솔 오류0/경고0, 스크린샷 확인. 제출·실제 은행 E2E는 아님.
- [x] 새 독립 리뷰 Critical0/Important0/Minor1. 유효한 state로 code/error 경계 검사, 토큰 크기·UTF16·Date, 저장commit 후 응답 유실을 보강하여 Minor 해소. 보완 후 서비스18+HTTP21개 통과.
- [x] Notion 기능10/A3 체크·현재 구현·다음 액션 갱신 및 재조회 확인.

일반 테스트 수는 legacy207 + contracts89 + database19 + API277 + web959 + E2E준비검사86이다.
실제 DB300개는 별도다. 최종 lint/typecheck/API build는 종료0이며 `git diff --check` 오류도 없다.
웹 production build·신규 원격 CI·의존성 감사·실계좌 침투 테스트는 이번에 실행하지 않았다.
로컬 웹 `https://localhost:3000`, API `127.0.0.1:3001`을 실행했고 `/health`의 `ok`를 확인했다.

이번 변경은 문서 포함27파일이다. 최초20~25파일 예상에서 안전 도구와 테스트 준비 코드를
역할별로 더 분리했다. 새 제품 코드의 최대 크기는 서비스92줄이며 새 의존성은 없다.

테스트용 DB 서버가 중단되어 있어 먼저 로컬 서버를 복구했다. 두 clock_timestamp 호출의
미세한 차이로 TTL 제약을 어긴 fixture는 statement_timestamp 기준으로 수정했다.
HTTP 검사에서 `Retry-After`의 필드명 불일치를 발견해 고쳤다. lint는 제어문자 정규식과
사용하지 않는 fixture 인수를 지적하여 코드 동작을 유지한 채 정리했다. 환경 오류와
의도한 기능 RED, 구현 결함을 구분해서 기록한다.

설계의 error 한도는 구현에 맞춰128 UTF-8바이트로 명확히 했다. 최종 리뷰가 판단하지 않은
공식 wire format·프록시·외부 로그·키 운영·정리 스케줄은 A6/운영 단계, BFF 쿠키·CSRF·세션
폐기·PC 연결 화면은 A4에 남긴다. 이를 이번 완료 범위에 포함시키지 않는다.

## 현재 사용할 수 있는 상태

가상 공급자는 테스트에만 주입한다. 앱 런타임은 `BANK_SERVICE=null`로 503을 반환한다.
따라서 PC에서 실제 은행을 연결할 수 있다는 뜻이 아니다. 코드·테스트가 있는 것과
포털 설정을 마치고 공식 테스트 서버에서 성공한 것은 다른 완료 조건이다.

## 후속

A4 BFF/쿠키/PC UI → A5 가상 전체 통합 → A6 공식 adapter/테스트 설정 순서로 이어간다.
IP 프록시 정책·외부 URL 로그 비노출·키 보관/회전·정리 worker·최소 권한 운영 DB 적용과
실계좌 자격 확인은 아직 별도다. 사용자에게 추가 secret을 채팅으로 요구하지 않았다.
