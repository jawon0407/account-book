# 2026-10-28 최신 서버 동의·철회 실기기 검증

> 이 문서는 같은 날의 선행 검증 이력이다. 후속 단일 상태 UI와 수집 기기 지정 연결, 최종 검증·인계는 [최신 결과](2026-10-28-collector-enrollment.ko.md)를 기준으로 본다.

## 현재 상태

최신 변경 결과는 **‘고정 목록 제거와 알림 허용 버튼’**, 실기기 최종 결과는 맨 아래 **‘새 팝업 실기기 검증 완료’** 절을 기준으로 본다. 재연결 후 새 팝업의 실제 표시·취소·설정 왕복·허용 반영·철회와 재실행 유지를 확인했다. 최종 서버 동의는 version 8/철회됨, OS 접근은 꺼짐이다.

**동의·권한 실기기 확인 단계를 완료했다.** 추가 활성화는 사용자 직접 조작으로 확인했고, 사용자가 동의와 OS 권한을 모두 해제한 뒤 앱의 ‘철회됨 / 허용되지 않음’과 서버 version 6 철회를 확인했다. 읽기 전용 재조회 후에도 유지됐다. 기준 커밋은 `be94992`다. 이전 원격 CI 통과와 아래 이번 검증은 구분한다.

후속 출처 선택·저장 첫 단위는 검증 후 사용자 요청으로 폐기했다. **최신 구현은 고정 목록 없는 ‘알림 허용’ 버튼 → 앱 팝업 → Android 설정 이동**이다. 실제 알림 본문 읽기·자동 거래 기록·시작/중지는 여전히 미구현이다. 커밋·푸시는 하지 않았다. 아래 출처 선택 기록은 당시 이력이며, 이번 변경의 결과는 문서 끝에 구분한다.

재로그인 완료: 로컬 DB·합성 인증 서버·API·HTTPS 웹·Metro를 재기동했다. 개발 CA를 지정하고 인증서 검증을 활성화한 HTTPS 로그인 페이지 응답 200, Metro 실행 상태를 확인했다. Windows curl의 사설 CA 폐기 상태 확인 실패는 별도 클라이언트 검증 문제였으며, TLS 검증을 끄지 않고 Node의 명시적 CA 검증으로 확인했다. 이후 USB 연결 1대, 앱 재시작·합성 계정 로그인·거래 내역 화면 도착을 직접 확인했다.

## 추가 동의 기록: 사용자 직접 조작으로 확인

1. 명시적 동의(version 1) 후 철회(version 2), 앱 재실행에서 철회 유지까지 확인했다.
2. 이후 최종 조회에서 별도 동의(version 3)가 발견돼 사용자 직접 조작 여부를 질문했다.
3. 다시 명시적으로 철회(version 4)한 뒤, 재실행과 상태 조회만 수행한 구간에서는 version 4와 철회 상태가 유지됐다.
4. 후속 읽기 전용 확인에서는 version 5의 동의 상태, 수집 기기 지정, Android 알림 접근 허용·서비스 연결이 관찰됐다. 이후 자동 조작을 멈췄다.

5. 사용자가 “켰었어”라고 직접 조작 사실을 확인했다. 따라서 위 추가 활성화는 사용자 조작으로 기록하며 자동 재동의 제품 결함으로 처리하지 않는다. 코드 검토에서도 자동 수락 경로는 발견하지 못했고, 통제된 재실행/조회 구간에서 철회 유지가 확인됐다. 모든 상황에서 결함이 없다는 일반적인 보증은 아니다.

재로그인 직후에는 동의 저장 유지·지정 기기 없음·OS 허용·서비스 연결 상태였으며, **사용자 해제 후 최종 확인은 동의 철회(version 6)·OS 허용되지 않음**이다. 기기 지정은 새 로그인 뒤 자동 재지정하지 않았다. 시스템 권한은 사용자가 직접 변경했다. 현재 서비스에는 알림 본문 처리 callback이 없어 금융 알림을 저장하지 않는다.

## 테스트 환경 문제와 한계

- 이전 임시 PostgreSQL은 처음 조회에서 합성 거래 2건이 있었으나 이후 내부 파일 누락 오류가 발생했다. 해당 서버를 중단하고 데이터 폴더는 보존했다. 기존 데이터를 복구했거나 보존 상태를 끝까지 검증했다고 주장하지 않는다.
- 별도의 새 임시 PostgreSQL(루프백 5437)과 합성 사용자 2명으로 시험했다. 새 환경의 금융 거래는 0건이다. 운영 Supabase와 실제 금융 데이터는 변경하지 않았다.
- API·가짜 인증 서버·웹·Metro는 로컬 시험용이다. 휴대폰은 USB 연결 경로를 사용하며 공개 인터넷 배포가 아니다. 합성 데이터 전용 DB 설정을 운영에 재사용하지 않는다.
- Windows C++ 경로 길이 문제 때문에 APK는 변경되지 않은 기존 네이티브 산출물을 재사용해 재패키징했다. 완전한 네이티브 클린 빌드 통과가 아니다. 네이티브 기능 수정 전 빌드 경로 문제를 해결하고 다시 빌드해야 한다.
- PC 브라우저는 별도의 테스트 프로필에서 검증한 개발 인증서의 공개키 지문만 예외로 지정했다. 전체 HTTPS 오류 무시는 사용하지 않았다. 일반 브라우저·시스템 신뢰 등록을 완료한 것은 아니다.
- Android 권한은 사용자가 켜고 끈 상태를 앱으로 돌아와 관찰했다. 자동으로 OS 권한을 바꾸지 않았다. 다른 기종·TalkBack·큰 글꼴 전체 검증은 수행하지 않았다.
- 실제 알림 처리, 서버 원문 전송, 백그라운드 수집, 새로운 원격 CI, 운영 침투시험은 이번 검증 범위가 아니다. 출처 선택 후속 작업의 전체 테스트는 별도 기록한다.

## 후속 완료 — 알림 출처 선택·계정별 저장

KB스타뱅킹·카카오뱅크·토스·카카오톡·문자의 준비용 복수 선택 화면을 추가했다. 기본은 선택 없음이며, 체크만으로 저장되지 않고 ‘출처 선택 저장’을 눌러야 반영된다. ‘선택 모두 해제’도 저장 전에는 초안이다. 실제 앱 설치 여부나 지원되는 알림 형식을 판별하는 기능은 아니다.

### 구현 구조와 규모

위 6개 파일은 각각 collector 또는 ui 폴더에 추가했다. 기존 `collector-screen.tsx`는 연결 2줄, `notification-access-panel.tsx`는 준비 안내 1문장만 수정했다. 기존 디자인을 유지하도록 surface brief도 갱신했다. 세션 관리자·서버 API·DB·Kotlin·의존성·PC 제품 코드는 변경하지 않았다.

저장 키는 서버 주소·사용자·설치 조합의 SHA-256 식별값이다. SHA-256은 키 이름을 만드는 용도이며 내용 보호는 기존 OS 보안 저장소가 담당한다. 저장 내용은 버전과 출처 ID뿐이다. 화면 세대 번호는 늦은 응답 차단에만 쓰며 저장 키에는 넣지 않는다. 다른 기기에서는 출처를 다시 선택해야 한다.

### 검증 및 보완

- 신규 테스트 26개를 포함해 모바일 243개와 도구 14개 통과. 전체 `pnpm test` 2,330개 통과(legacy 208, contracts 197, database 19, mobile 243+14, API 333, web 1,225, E2E preflight 91). 별도의 실제 DB 통합 시험 전체나 E2E 전체를 뜻하지 않는다.
- 모바일 타입 검사, 루트 lint, `git diff --check` 통과. 실제 Android에서 새 JS bundle을 실행했다. 네이티브 클린 빌드와 새 원격 CI는 수행하지 않았다.
- 실기기: 기본 0개 → KB·토스 2개 선택 저장 → 화면 재진입 복원 → 앱 재실행 복원 → 전체 해제 저장 → 재진입 후 0개 유지 확인. 동의 철회·OS 접근 꺼짐 상태에서도 설정만 저장 가능하며 수집은 시작하지 않는다.
- PC Playwright: 합성 로그인 → 내 계좌 → 새로고침 → 로그아웃 통과. PC 기능 확장이나 거래 동기화 전체 시험은 아니다.
- 독립 검토의 최초 판정은 `DONE_WITH_CONCERNS`(Important 1, Critical/Minor 0)였다. 동일 계정에서 저장 중 화면 재진입 시 이전 쓰기가 최신 선택을 덮는 문제를 실제 구현으로 재현했다. 화면 수명 밖에서 동일 저장 범위의 읽기·쓰기를 순서대로 처리하도록 고쳤고 회귀 테스트 RED→GREEN 및 전체 테스트를 통과했다. 재검토자의 전체 무결점 승인으로 과장하지 않는다.
- Impeccable 문서 검증: 기존 Bookify 색상·서체·56dp 선택 행·48dp 버튼 유지. 새로운 전역 디자인/래스터 없음. 큰 글자·TalkBack·다크 모드·다른 OEM은 미검증이다. root DESIGN.md의 모바일 미구현 설명은 기존 드리프트로 이번에 임의 수정하지 않았다.

### 남은 작업과 종료 상태

이번 단위는 **출처 선택·저장까지**다. 다음은 시작/중지 안전 상태 계약(서버 동의·유효 세션·지정 기기·OS 권한·선택 출처) → Android 정상 빌드 경로 확보 → 실제 알림 처리 연결 순서다. 원문 재전송 큐, 알림 파싱, 자동 거래 저장은 아직 없다.

휴대폰은 합성 계정·출처 0개, 동의 철회·OS 접근 해제 상태로 두었다. 테스트 서버는 로컬에서 실행 중이다. 시험을 끝내면 USB 디버깅을 끄고 보안 설정을 복원해도 된다. 현재 변경은 기능 브랜치에 미커밋 상태이며 커밋·푸시·배포하지 않았다.

## 최신 결과 — 고정 목록 제거와 알림 허용 버튼

사용자 요청에 따라 위 출처 선택 구현은 폐기했다. 고정 5종 목록·선택 저장·모델·패널 및 관련 테스트 6파일을 제거했다. 개발용 저장값은 더 이상 읽거나 적용하지 않으며 금융 원문을 저장한 값도 아니다. `collector-screen.tsx`는 이전 새 패널 연결을 제거해 HEAD 내용으로 돌아왔다.

### 현재 사용자 흐름

1. 수집 설정의 **알림 허용**을 누른다. 바로 동의하거나 OS 권한을 켜지 않고 Account Book Dev 안내 팝업을 연다.
2. **취소**는 요청 없이 닫는다. **동의하고 설정 열기**는 서버 저장 응답을 검증한 뒤 Android 알림 접근 설정을 연다. 최신 동의가 있으면 **설정 열기**만 제공하고 다시 저장하지 않는다.
3. Android 화면에서 사용자가 Account Book Dev를 직접 선택·허용한다. 앱 팝업은 OS 허용 팝업을 흉내 내지 않는다. 돌아오면 실제 OS 상태를 다시 읽는다.
4. 동의 철회·재조회는 유지한다. 이미 OS 접근이 켜졌으면 서버 오류 중에도 **Android 알림 접근 관리**로 가서 끌 수 있다.

일반 알림 표시 권한(POST_NOTIFICATIONS)을 요청하는 것이 아니다. Android의 [알림 접근 설정 공식 계약](https://developer.android.com/reference/android/provider/Settings#ACTION_NOTIFICATION_LISTENER_SETTINGS)을 기존 네이티브 모듈로 연다. 고정 목록 제거가 모든 금융 형식을 현재 분석한다는 의미는 아니며, 실제 본문 수집·분류·업로드·시작/중지는 여전히 미구현이다. 현재 허용된 동의를 일반 대화·인증번호의 무제한 수집 허가로 확대 해석하지 않는다.

### USB 재연결 확인 요청 이후 점검

사용자의 실기기 검증 요청으로 재확인했으나 ADB 장치 0대, Windows의 현재 Android/Samsung/ADB/MTP USB 장치도 0개였다. 미승인(unauthorized) 장치가 보이는 상태가 아니라 장치 자체가 디버깅 목록에 없다. 드라이버나 보안 설정을 임의로 변경하지 않았다.

localhost 테스트 스택 3000/8081/4510/4511/5437은 실행 중이며, 합성 DB의 동의는 version 6/철회됨으로 유지된다. 앱 팝업 조작은 시작하지 못했다. 사용자에게 데이터 케이블 재연결·잠금 해제·USB 디버깅 승인·앱 열기를 요청했다. 새 팝업 실기기 검증은 계속 미완료다.

안전 장치도 동작했다. 서버 저장 직후 즉시 조회한 한 차례는 아직 앱 화면이었고, 후속 읽기에서 설정 이동 완료를 확인했다(비동기 전환). 테스트 도중 화면이 자동화의 예상과 달라진 구간에서는 전면 앱/버튼 가드가 입력을 중단했고, 새 화면을 확인한 뒤 재현했다. 그 구간의 조작 주체는 단정하지 않으며, 이를 제품 결함이나 자동 권한 변경으로 오인하지 않는다.

제품 코드 추가 수정 없이 기존 구현을 검증했다. 이번에 전체 2,311개 자동 테스트를 다시 실행한 것은 아니며, 그 수치는 앞선 구현 검증 결과다. 새로 실행한 것은 위 실기기 시나리오와 PC Playwright 회귀다. OS 권한은 사용자가 직접 선택했고 자동화가 강제로 부여·해제하지 않았다. 실제 수집·원문 분석·자동 저장, 다른 기기/OEM·가로 화면·큰 글꼴·TalkBack은 이번 검증 범위가 아니다.
