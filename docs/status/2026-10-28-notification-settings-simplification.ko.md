# 알림 상태 한 줄·통합 새로고침·상세 팝업

> 후속 확인 완료: 같은 날 [수집 기기 연결 작업](2026-10-28-collector-enrollment.ko.md)에서 USB 실기기·독립 리뷰를 진행했다. 아래 초기 미검증 기록은 이력이며, 최신 결과는 마지막 절 및 후속 문서를 따른다.

## 반영한 요청

1. 사용자는 처음 ‘계정·설치의 동의’ 의미를 질문했고, 설명 후 두 상태 대신 ‘알림 여부’ 한 줄로 바꾸도록 요청했다. 서버 동의와 Android 접근을 내부에서는 계속 별도로 판단한다.
2. 기존 큰 새로고침 버튼 두 개를 상단의 작은 ‘새로고침’ 한 개로 통합했다. 두 모델을 함께 읽으며 저장/조회 중에는 비활성화한다.
3. 하단의 긴 안내를 소개 문단 옆 둥근 ‘자세히 알아보기’ 버튼과 읽기 전용 팝업으로 옮겼다. 좁은 화면에서는 문단 다음 줄로 배치되며 최소 48dp 조작 영역, 14sp 버튼 글씨를 유지한다. 닫기 버튼과 Android 뒤로가기 처리를 구현했다.

## 표시 판정

| 조건 | 알림 여부 |
| --- | --- |
| 최신 서버 동의 + Android 접근 허용 | 허용됨 |
| 동의 없음/철회/고지 변경 또는 Android 접근 거절 | 허용되지 않음 |
| 조회 또는 저장 중 | 확인 중 |
| 알려진 비허용이 없고 서버 오류·응답 없음·OS 조회 실패·네이티브 미지원 | 확인 필요 |

‘허용됨’은 실제 자동 기록 중이라는 뜻이 아니다. 수집 기기 지정과 실제 처리 기능은 별개다. 현재 APK의 금융 알림 본문 수집·분석·업로드는 미구현이다. 동의 철회·이미 켜진 OS 접근의 관리 동작을 유지했다. 팝업 열기/닫기·재조회는 동의나 권한을 변경하지 않는다.

## 변경 파일과 분리

- `apps/mobile/src/ui/collector-screen.tsx`: 두 모델 수명을 상위에서 관리, 통합 재조회. 설정 복귀의 기존 세션 재검증·재조회 유지.
- `apps/mobile/src/ui/notification-access-panel.tsx`: 모델 주입·단일 상태·안내 위치. 동의/철회/OS 관리 정책 변경 없음.
- `apps/mobile/src/ui/notification-access-guide.tsx`: 기존 안내를 Modal로 이동, 상태 의미 추가.
- `apps/mobile/src/collector/notification-consent-copy.ts`: 단일 표시값을 파생하는 조건 추가.
- `apps/mobile/src/collector/notification-consent-copy.test.ts`: 상태 판정 12개 추가. 레이아웃만의 새 테스트 파일은 만들지 않았다.

서버·DB·로그인 정책·Kotlin·의존성·PC 제품 코드 변경 없음. 이전 미커밋 작업을 보존했으며 커밋·푸시·병합·배포는 하지 않았다.

## 검증

- 통합 표시: RED 12실패/기존10통과 → GREEN. 모바일 전체 236테스트 통과(기존224 + 신규12).
- 기존 도구 테스트 14개 통과. 모바일 타입 검사 2종, 루트 lint 및 diff 공백 검사 통과.
- Android JS/Hermes export 성공. 새 APK 빌드·설치가 아니다.
- PC Playwright: 합성 계정 로그인 → 내 계좌 → 새로고침 → 로그아웃 통과. 모바일 팝업 검증을 대신하는 결과가 아니다.
- 첫 일부 pnpm 명령은 내부 실행기의 Node 24.19.0 선택으로 프로젝트 요구 Node 22.15.1과 충돌했다. 의존성 파일을 수정하지 않고 지정 Node 22로 동일 도구를 직접 실행하여 검사를 통과했다.
- 독립 리뷰를 요청했으나 검토 에이전트 사용량 제한으로 실행되지 않았다. 작성자의 diff 자체 검토는 진행했으나 독립 보안·코드 리뷰 통과로 표현하지 않는다.
- USB 연결 기기 0대. 이번 단일 상태/새 팝업의 실기기, 뒤로가기 실제 동작, 큰 글꼴/TalkBack/가로 화면은 미검증이다. 앞선 권한 Alert의 기기 검증 결과를 재사용하지 않는다.

## 승인됐지만 남은 다음 단위

여러 기기 로그인은 유지하고 자동 수집만 계정당 1대로 제한한다. ‘알림 허용’ 흐름에서 동의와 OS 권한을 확인한 뒤 수집 기기를 설정하고, 다른 기기에서 옮길 때 명시적으로 확인한다. 권한 거절/설정 취소 시 기존 수집 기기는 유지한다. 이번 UI 정리에는 이 연결을 포함하지 않았고 기존 수동 지정 UI가 남아 있다. 계정 전환·설정 앱 왕복·동시 교체·응답 유실을 다루는 별도 기능 단위다.

## 구현 판단

- 개발용 톱니바퀴와 제품 UI를 결합하지 않고 화면 상단 텍스트 새로고침으로 구현했다. 아이콘 추가 의존성 없음.
- 허용/비허용 두 값만 강제로 표시하면 서버 오류를 거절로 오해하므로 일시 상태는 확인 중/확인 필요로 구분했다.
- Impeccable의 단순화·정보 점진적 공개 기준을 적용했으나 실제 시각 검증은 기기 연결 후 남아 있다.

## 후속 실기기·독립 리뷰

- 실제 Android 1대에서 통합 새로고침·자세히 알아보기·끝 문단까지 스크롤·고정 닫기·Android 뒤로가기 후 설정 화면 유지 확인. 안내만 열고 닫은 동안 서버 동의 version 8/철회 상태가 유지됐다.
- 독립 리뷰의 Important 1건: 알려진 거절보다 다른 상태의 조회 실패가 우선 표시됨. 재현 시험 4건 실패 확인 후 수정했고, 불확실 조합 3건도 추가하여 표시 시험 25개 통과.
- 기존 세로 화면·글꼴 기준이다. 큰 글꼴·TalkBack·다른 OEM은 아직 미검증.
- 후속 사용자 승인으로 수집 기기 연결과 함께 커밋·푸시 범위에 포함한다. 원래의 ‘미커밋 인계’ 지시는 후속 승인으로 대체됐다.
