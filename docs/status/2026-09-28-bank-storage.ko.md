## 검토에서 결정한 사항과 한계

- 공급자 식별자는 복원 가능한 암호화 봉투로 저장한다. 조회 어댑터 계약이 달라지면 migration/매핑을 보완해야 한다.
- 함수 PUBLIC 권한은 생성 transaction에서 개별 철회한다. 다른 schema 전역 기본권한을 건드리지 않는 대신 후속 함수도 철회 누락 검토가 필요하다.
- 검증 로그를 삭제하지 않고 보존한다. 디스크 사용량은 늘지만 감사·재개 근거를 유지한다.
- 테스트에 기존 Drizzle0.45.2를 직접 연결한다. 새 버전·운영 패키지는 없으며 test importer와 lock3줄만 늘었다.
- 원자적 상태 전이·현재 시각 만료·요청 제한·정리는 A2.2/A2.3이다. 이것이 없으면 실제 금융 연결을 서비스할 수 없으므로 운영 활성화하지 않는다.
- 은행 HTTP/BFF/UI/운영 secret은 후속이다. 따라서 이 작업만으로 사용자가 계좌를 연결할 수는 없다.
- 실제 조회 패턴의 인덱스·용량 검토는 API 구현 단계에서 한다. 이후 index migration과 출시 전 지연 검증이 필요할 수 있다.
- SQL fixture는 봉투 모양만 검증한다. GCM 진위는 API가 검증하며 DB 형식 통과를 진짜 토큰 인증으로 취급하지 않는다.

초기 기능 diff24파일 +911/-4(진행 문서 정합성 갱신 제외). 역할별로 나누고 검증 보완 파일2개와 테스트 의존성 연결을 추가해 첫 예상보다 파일 수가 늘었다. 앱의 외부 공개 API나 운영 DB는 변경하지 않았다.

PR18 최종 diff는 문서 정합성 갱신을 포함해 27파일 +946/-11이다. main 보호·필수 검사·관리자 적용을 유지했고 우회 병합을 하지 않았다. 병합 뒤 최신 현황 및 A2.2 사전 점검 문서는 다음 기능 브랜치에서 기록한다. A2.2 제품 코드가 이미 구현됐다는 뜻은 아니다.
