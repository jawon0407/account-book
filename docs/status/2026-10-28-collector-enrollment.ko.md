# 알림 허용 → 수집 기기 설정 연결 결과

## 이번에 완성한 동작

여러 모바일·PC 로그인은 그대로 유지한다. 별도의 ‘이 기기 지정/변경’ 버튼 대신 **알림 허용 → 선택 동의 확인 → Android 접근 확인 → 수집 기기 지정**으로 이어진다. 다른 기기가 이미 지정되어 있으면 교체 여부를 추가로 확인한다. 기기 지정 해제와 동의 철회는 계속 별도 선택이다.

허용 여부는 한 줄로 표시한다. 서버 동의와 Android 접근을 둘 다 확인해야 허용됨이다. 한쪽의 거절/철회를 확인했다면 다른 쪽 조회 실패에 가리지 않고 허용되지 않음으로 표시한다. 둘 다 판단할 수 없는 경우는 확인 필요다. 안내는 작은 ‘자세히 알아보기’ 팝업이며 통합 새로고침은 화면 상단에 있다.

**실제 금융 알림 읽기·파싱·자동 거래 저장·수집 시작/중지는 아직 미구현이다.** 이번 작업은 안전한 설정 연결이다. DB·서버 API·로그인 정책·Kotlin·의존성·PC 제품 코드는 변경하지 않았다.

## 코드 흐름 — 초급 개발자용

1. `app/index.tsx`가 `CollectorEnrollment`를 만든다. Android 설정이 전면에 나가면 장부 화면은 숨기되, 사용자가 시작한 설정 의도만 메모리에 잠시 보관한다. 토큰이나 금융 알림 원문을 여기에 넣지 않는다.
2. `notification-access-panel.tsx`가 설명 팝업을 연다. 확인 콜백은 팝업을 띄운 화면 세대에 묶인다. 그 사이 화면/계정이 바뀌면 오래된 확인은 무시한다.
3. `collector-enrollment.ts`는 기존 `NotificationAccess`로 동의를 저장하고 최신 OS 상태를 읽는다. 아직 OS 접근이 없으면 Android 설정으로 이동한다. 앱이 권한 스위치를 대신 켜지 않는다.
4. 복귀하면 로그인과 동의·OS·기기 지정 상태를 다시 읽는다. 같은 서버/계정/설치/로그인 세대이고 10분 이내이며 OS 설정 열기 성공까지 확인한 의도만 이어간다. 재시작하면 메모리가 없어지므로 사용자가 다시 시작한다.
5. 지정이 없으면 `CollectorSettings`의 기존 API로 한 번 지정한다. 다른 기기가 있으면 별도 확인을 기다린다. 조회한 버전이 바뀌거나 응답이 유실되면 자동으로 덮어쓰거나 저장 요청을 재전송하지 않는다.

기존 모델을 조합했기 때문에 서버의 계정당 수집 기기 1대 검사와 동시 수정 버전 검사를 그대로 사용한다. 설정 화면에서 나가기·철회·교체 취소는 미완료 의도를 버린다. 일반 로그인이나 장부 동기화는 제한하지 않는다.

## 독립 리뷰와 수정

| 발견 사항 | 처리/검증 |
| --- | --- |
| 알려진 거절이 다른 상태의 조회 오류에 가림 | 4개 재현 실패 확인 → 조건 우선순위 수정. 진짜 미확인 조합 3개도 추가. 표시 시험 25개 통과. |
| background 뒤 늦은 OS 설정 열기 실패가 의도를 남김 | false/예외 2개 실패 재현 → OS 성공 확인 표시와 의도 동일성 검사 추가. 늦은 실패는 폐기하고 성공한 설정 왕복만 재개. |
| 이전 Native Alert 콜백의 수명 | 추가 방어: 표시 당시 화면 세대를 캡처. 새 계정/새 화면에서 오래된 확인은 동의·지정하지 않음. |

최종 독립 리뷰는 추가 Critical/Important를 발견하지 못했다. 독립 검토자의 Vitest는 임시 파일 rename 권한 문제로 수집 전에 중단됐으므로, Node 22 메모리 실행으로 경계 사례를 확인했다. 아래 전체 회귀는 주 작업자가 실행한 결과이며 독립 검토자가 모두 재실행했다고 주장하지 않는다. 운영 보안 감사/침투 테스트 완료를 뜻하지 않는다.

## 자동 검증

- 새 연결 모델 24개, 기존 권한 모델 28개, 표시 25개. 계정/설치/서버/세대 변경, 만료/시간 역행, 권한 거절, 교체 취소, 저장 실패, 응답 지연, 중복 확인, OS 열기 실패, 오래된 팝업 등을 포함한다.
- 최종 `pnpm test`: **2,350개 통과**, 실패 0. legacy208 / contracts197 / database패키지19 / mobile263+도구14 / API333 / web1,225 / E2E preflight91.
- 모바일 타입 검사 2종, 루트 ESLint, diff 공백 검사 통과.
- Android JS/Hermes export 성공. 네이티브 APK 새 빌드·설치와 다르다. 기존 개발 APK가 최신 Metro 코드로 동작한다.
- PC Playwright: 격리 브라우저의 합성 계정 로그인 → 내 계좌 → 새로고침 → 로그아웃 통과. 인증서 예외는 이 테스트 인증서 공개키로 제한했다.
- 별도 실제 PostgreSQL 동시성 전체 스위트는 이번에 재실행하지 않았다. DB/API 변경이 없으며 모바일 모델의 충돌 분기와 기존 서버 단위 회귀를 실행했다. 테스트 도구 권한/Node 버전 문제는 제품 실패와 구분했다.

## 실기기 확인 범위

실제 Android 1대, 현재 세로 화면·글꼴에서 로컬 합성 계정만 사용했다. 실제 비밀번호·금융 거래 알림은 사용하지 않았다.

- 안내 Modal: 끝 문단까지 스크롤, 고정 닫기, Android 뒤로가기 뒤 설정 화면 유지. 조회/안내 조작 중 동의 version8/철회 유지.
- 신규 동의 Alert: 전체 본문·취소·확인 표시 확인. 동의 저장 version9 이후 Android 접근 설정으로 이동. 이동만 했을 때 OS false였고 지정 버전은 변하지 않았다.
- 권한을 켜지 않고 돌아온 경우: ‘허용되지 않음 / 지정된 기기 없음’, 지정 변경하지 않았다는 안내 확인.
- 이후 실제 OS true와 ‘허용됨 / 이 기기가 지정되어 있어요’, 서버 지정 version3 확인. 자동화가 OS 스위치를 조작하지 않았다. 허용 조작 자체는 직접 관찰하지 못해 성공 상태 반영과 구분한다.
- 재확인 구간에서 동의9·지정3 유지. 팝업이 자동 입력 전에 닫힌 구간은 누가 누른 것인지 단정하지 않으며 완전 자동화 반복 시나리오로 주장하지 않는다. 중복 쓰기 방지는 모델 시험으로 별도 검증했다.
- 명시적 ‘지정 해제 확인’으로 미지정 복귀, ‘동의 철회 확인’으로 비허용 복귀 확인. 사용자가 OS 해제·앱 복귀를 확인했다.
- 마지막 사용자 답변 뒤 USB 기기가 0대로 바뀌어 OS 해제 상태의 추가 자동 재조회는 하지 못했다. ‘OS 끔’은 사용자 확인이고, 도구로 마지막 관찰한 서버 상태는 별도로 대조한다. 이 차이를 검증 완료로 덮지 않는다.
- 서버 최종 대조: 동의 version10/철회, 수집 지정 version4/미지정. 기존 거래를 삭제하거나 운영 DB를 변경하지 않았다.

큰 글꼴·TalkBack·가로 화면·다른 OEM·실제 여러 휴대폰 동시 교체는 미검증이다. 화면이 바뀌면 전면 앱/버튼 가드로 입력을 중단하고 새 상태를 확인했다. 원본 화면·기기 식별자·비밀값은 Git/Notion에 전송하지 않는다.

## 인계

계획: [수집 기기 연결](../superpowers/plans/2026-10-28-collector-enrollment.md). 이전 UI/권한 진입 작업을 함께 사용자 승인 범위로 커밋·푸시한다. 과거 ‘미커밋’ 문구는 해당 시점의 이력이며 이번 승인으로 대체됐다. 병합·운영 배포는 하지 않는다.

다음 기능은 수집 시작/중지 안전 상태와 실제 금융 알림 선별이다. 이번 설정 완료를 금융 알림 자동 저장 완료로 오해하지 않아야 한다. 실기기 검증 종료 후 USB 디버깅과 사용자 보안 설정을 복원할 수 있다.
