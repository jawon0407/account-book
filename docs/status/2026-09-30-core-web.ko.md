# PC 장부 기본 관리 화면 구현·검증

기준: 2026-09-30, `feature/bank-state-transitions` / HEAD `10ec214` 위의 미커밋 변경. [계획](../superpowers/plans/2026-09-30-core-web.md), [설계](../superpowers/specs/2026-09-30-core-web-design.md), [사용법](../guides/core-web-usage.ko.md), [코드 흐름](../guides/core-web-development.ko.md).

## 구현한 범위

| 화면 | 가능한 작업 | 아직 없는 작업 |
| --- | --- | --- |
| `/app` | 본인 계좌 조회·종류/보관 필터·추가·이름 변경·보관·장부 잔액 표시 | 실제 은행 연결, 시작 잔액·거래 입력, 보관 복원 |
| `/app/categories` | 수입/지출 분류 조회·추가·이름/순서 변경·보관 | 거래 분류 화면, 보관 복원 |
| `/app/profile` | 닉네임 수정, 가입 경로·역할 확인 | 사진 업로드, 역할 변경, 탈퇴 |

빈 계정에는 실제 빈 목록을 표시한다. 가짜 거래/통계는 넣지 않았다. 계좌 생성은 은행 API 연결이 아니다. 모바일 폭 검사는 웹 반응형 검사이며 별도 Android/iOS 앱의 구현 증거가 아니다.

## 작업 규모와 파일

장부 기능은 `apps/web/src/features/ledger`의 TS/TSX 13개와 CSS 1개로 나눴다. 각 구현 파일은 14~90줄이며 주석·매개변수 설명을 포함한다. `apps/web/src/app/app` 경로 파일 4개는 얇게 화면만 연결한다. 장부 단위 테스트 파일 7개, `tests/e2e/core`의 준비·실행·설정·시나리오 파일 4개를 추가했다. 문서는 사용법·코드 흐름·현재 기록을 새로 쓰고 제품·디자인·프론트·BFF 색인을 갱신했다.

기존 `server/core/core-controller.ts`와 테스트에 기대 사용자 일치 검사를 추가했다. `.gitignore`는 Next 로컬 인증서와 Playwright 결과를 제외하며 기존 env 제외 규칙은 유지했다. `tests/e2e/package.json`에 `test:core`, TypeScript 검사 범위에 `core/**/*.ts`를 추가했다. 새 의존성·DB migration·API 경로·권한 확대는 없다.

## 보안·일관성 보완

1. 브라우저 요청은 같은 출처 BFF, 입력·응답 공유 계약 검사, POST/PATCH CSRF, 변경 자동 재시도 없음.
2. 사용자별 메모리 QueryClient와 query key. 인증 재확인 중 이전 화면을 닫고, 계정 변경·만료·로그아웃에 사설 캐시 정리.
3. `X-Account-Book-User`가 실제 쿠키 사용자와 다르면 BFF가 Nest 전송 전에 401. 헤더는 추가 조건일 뿐 권한 근거가 아니다. UI는 항상 보내고 기존 소비자 호환상 BFF에서 생략은 허용한다.
4. 열린 생성 폼의 같은 정규화 입력은 같은 UUID 요청 키. 응답 불명 시 입력 유지. 다른 입력 또는 새 폼은 새 의도다.
5. 수정/보관은 읽었던 expectedVersion. 실제 동시 수정 시 409 안내·덮어쓰기 금지·명시적 재조회.
6. 프로필 저장이 화면 이탈 후 끝나도 지운 캐시를 재생성하지 않는다. 로그아웃 중에는 이동 링크를 표시하지 않으며 서버 완료/실패를 구분한다.
7. 저장 중 중복 제출 차단, 고정 한국어 오류, 영구 금융 캐시/서비스워커 추가 없음. 로컬 인증서 개인키·env·테스트 산출물 Git 제외 확인.

인증 재검사 때 같은 사용자라도 미저장 입력을 잃을 수 있다. 이를 금융 데이터가 잘못된 계정에 적용되는 것보다 우선한 현재 절충으로 기록했다. 운영 브라우저/OS 전체 흔적 삭제를 보장하는 구현은 아니다.

## 발견한 문제와 수정 경위

- 실제 브라우저에서 목록이 로딩에 남았다. StrictMode의 effect 정리와 새 조회가 충돌하는 것을 단위 RED로 확인하고, 같은 인스턴스 재검사와 실제 이탈을 구분했다.
- DB 정리가 서버 pool 종료보다 먼저 실행돼 실패했다. 테스트 실행기를 분리해 Playwright 서버 종료 뒤 정리하도록 했다. 연결 강제 종료/기존 DB 덮어쓰기는 하지 않았다.
- 독립 코드 리뷰 Important 1건: 신원 재조회 중 A 계정 UI가 남아 B 계정 쿠키로 요청할 수 있었다. UI 잠금 + 요청 사용자 결합 + BFF 일치 검사와 회귀 검사로 보완했다.
- 리뷰 Minor: 늦은 프로필 응답의 캐시 복원과 테스트 설명의 과장. active 상태 검사를 추가하고 실제 expectedVersion 전송 테스트를 작성했다. 브라우저에서도 동시 수정·잘못된 응답·긴 이름·음수 표시 범위를 확대했다.
- Playwright에서 로그아웃 응답 전 링크를 따라가면 요청 완료를 기다리지 못했다. pending 동안 이동 링크를 숨기고 완료 후 재접근까지 검사했다.
- 테스트 자체의 Next route-announcer 중복 alert 선택, 실제 버튼명과 다른 선택자, axe 기본 import의 NodeNext 타입 문제도 수정했다. 실패를 통과로 집계하지 않았다.
- 디자인은 구조/타입 평가와 기계 스캔을 분리했다. 넓은 dialog 그림자 제거, 글꼴/간격 정리 후 실제 스크린샷을 확인했다. 자동 검사 0건을 전체 UX 보증으로 해석하지 않는다.

## 남은 순서

1. 거래 조회·생성·수정·삭제 표시 API와 PC 입력 화면: 계좌·분류 소유권/활성 상태, 날짜·정수 금액, 멱등성·version·잔액 반영 검증.
2. 시작 잔액·장부 내 계좌 이체: 두 거래 원자성, 같은 계좌 거부, 보관 계좌·버전·동시성 검증. 실제 송금 기능은 아님.
3. 은행 연결 상태 처리·동의·조회·수집과 중복 복구. 실제 공급자 계약/운영 권한과 비용은 별도 사용자 확인 사항.
4. 별도 React Native/Expo 모바일 앱과 같은 사용자·원장 사용 검증.
5. 운영 OAuth·rate limit/abuse·풀러·백업 복구·경보·개인정보 고지·한국망 p95 및 출시 보안 검증.

앞선 인증·DB·API의 미커밋 변경을 보존했다. 이번 작업에서 커밋·푸시·PR·배포·hosted 금융/프로필 시험 쓰기는 하지 않았다. 기존 기능 브랜치와 worktree는 유지한다. [공통 작업 절차](../guides/change-workflow.ko.md)에 다음 PC 웹 변경도 실제 Playwright 검증을 필수로 수행하도록 기록했다.
