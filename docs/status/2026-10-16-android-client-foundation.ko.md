# Android 앱 첫 기반 — 구현·검증 기록

기준: 2026-10-16, `ledger-public-contracts` 작업 트리, `feature/bank-state-transitions`, HEAD `8af7a0d` 이후 미커밋 변경. 이 문서는 이전 인증/서버 기록 이후의 **모바일 클라이언트 단위**다. 원격 main, 배포, 실제 DB의 상태를 뜻하지 않는다.

후속: [Android 의존성 보완](2026-10-16-android-dependency-remediation.ko.md)에서 URI 디코더를 공식 수정판으로 교체해 감사 경고가 3→2건으로 줄었다. 아래 첫 기반 수치는 당시 기록이다.

[Notion 07 현재 진행 상황](https://app.notion.com/p/3e2323168ba681b59204c2342edb27b3), 04 기술 구조와 최상위 페이지를 갱신했고 저장 성공 및 다시 읽기로 반영을 확인했다. 이전 단계의 기록은 당시 상태로 보존했다.

## 이번에 가능한 것

`apps/mobile`에 이메일 로그인 → 같은 서버 장부 목록 → 새로고침/추가 조회 → 로그아웃 코드를 추가했다. Android 우선이며 iOS 구현은 시작하지 않았다. Bookify 인증/목록 참조를 적용했지만 실제 Android 화면의 시각 검증은 아직 하지 못했다.

| 구분 | 현재 상태 |
| --- | --- |
| 모바일 인증·목록 코드 | 로컬 구현 |
| 모바일 자동 테스트 | 순수/어댑터 39개 + Windows 번들 도구 회귀 4개 통과 |
| 모바일 TypeScript | 앱 선언 검사 + 순수 코어 엄격 검사 통과 |
| Android JavaScript/Hermes 번들 | 1,368모듈, 3.3MB 번들 생성·종료 0 |
| APK 제작·에뮬레이터·실기기 | 미검증. 표준 경로/PATH에서 SDK/JDK/adb를 확인하지 못함 |
| 실제 서버 로그인·금융 데이터 | 미검증. 합성 단위 시험과 번들이 실서버 성공을 대신하지 않음 |
| 알림 수집·자동 기록 | 미구현 |
| 커밋/푸시·원격 CI·PR 병합·배포 | 이번 단위에서 수행하지 않음 |

현재까지의 전체 회귀 결과는 아래 최종 검증 절에 별도로 기록한다. 과거 인증 보고서의 감사 0건은 이번 모바일 의존성 추가 후의 결과가 아니다.

## 개발 흐름을 읽는 방법

1. `app/index.tsx`가 앱 상태를 구독한다. 로그인 전에는 입력 화면, 확인된 세션에서는 목록, 저장소/통신 오류에서는 안전한 안내를 보여 준다.
2. 화면은 `SessionManager`에 이메일/비밀번호 또는 조회 요청만 전달한다. 토큰을 화면 state에 공개하지 않는다.
3. `SessionManager`는 인증 작업을 순서대로 실행한다. 계정 세대 번호로 로그아웃 전에 시작된 응답을 거부하고, 최신 foreground 검증만 화면을 다시 열 수 있다.
4. `NativeClient`는 origin이 고정된 HTTPS BFF의 정해진 경로를 호출한다. 자동 재시도는 없고 본문 읽기까지 10초 제한이 걸린다. 입력/응답은 공용 계약으로 검증한다.
5. `androidTransport`는 `expo/fetch`에 리디렉션 거부와 쿠키 미사용을 다시 명시한다. React Native 기본 fetch의 옵션 처리만 믿지 않는다.
6. 세션과 설치 UUID만 SecureStore에 보관한다. 거래 목록·비밀번호·이메일·서버 비밀키는 영구 저장하지 않는다. 거래는 50개씩 읽고 페이지의 합계를 전체 합계로 표시하지 않는다.

초급 개발자용 파일 지도·실행 명령은 [모바일 README](../../apps/mobile/README.md)에 있다.

## 중요한 현재 제한: 완전 재실행 시 재로그인

보안 저장소의 tombstone 쓰기와 삭제, 네트워크 서버 철회가 동시에 실패할 수 있다. 이 상태에서 저장된 토큰을 자동 복원하면 로그아웃한 이전 계정이 다시 열릴 수 있다. 따라서 **현재 개발 버전은 프로세스를 완전히 다시 시작하면 잔존 토큰을 정리/철회만 시도하고 자동 로그인하지 않는다.** 같은 프로세스의 background 복귀는 서버 재검증한다. 로그인 화면에도 이를 안내한다.

이는 출시 UX 확정이 아니다. 알림 수집은 앱 프로세스 재시작에도 안전하게 동작해야 하므로, 수집기 착수 전에 지속 로그인/철회 상태의 내구성을 별도 설계·검증한다. 오프라인 로그아웃으로 서버의 모든 자격 증명까지 폐기했다고 주장하지 않는다.

## 리뷰 지적과 처리

독립 코드·보안 리뷰 1회에서 Critical 0, Important 4, Minor 2가 나왔다. Important는 실패 테스트를 먼저 확인한 뒤 한 번의 수정 묶음으로 반영했다.

| 중요 지적 | 수정 및 근거 |
| --- | --- |
| RN 기본 fetch가 redirect 옵션을 강제하지 않음 | Expo native 전송을 명시하고 Request 옵션 유실에도 다시 강제하는 어댑터 테스트 추가. 실제 Android TLS/redirect는 후속 기기 게이트 |
| foreground 검증 실패·중첩 때 장부가 열릴 수 있음 | manager의 verifying 상태와 검증 순번으로 차단. 최신 검증 성공만 ready 발행 |
| 이전 토큰으로 보낸 목록의 늦은 401이 새 세션을 지울 수 있음 | 인증 큐 안에서 계정 세대와 현재 토큰을 다시 비교. refresh-required와 진짜 만료를 구분 |
| 저장소/서버 철회 동시 실패 뒤 재실행 시 이전 계정 복원 | cold-start 재로그인 정책, 메모리 내 실패 철회 재시도, 잔존 세션 재사용 금지 |

중간 RED는 세션 실패 6개와 새 어댑터 모듈 부재를 확인했다. 수정 후 39개 테스트가 통과했다. 별도 네이티브 실기기 리뷰나 전체 PR 리뷰를 완료했다는 뜻은 아니다.

Minor 중 문서 버전/체크리스트/README 누락은 이번 기록에서 보완한다. 다른 Minor인 본문 크기 검사는 여전히 후속이다: 현재 Content-Length와 읽은 문자열을 검사하지만, 수신 단계의 정확한 바이트/메모리 상한은 아니다. 서버 제한과 별개로 스트리밍 상한 및 과대 응답 기기 시험을 출시 전에 보강한다.

리뷰 범위 밖/판단 보류: APK 시작·실제 TLS·키보드·Back·글자 확대·TalkBack·최근 앱 스냅샷·Figma 시각 일치·서명/스토어, 알림 listener/파서·쓰기/필터/환불/통계·iOS, 기존 혼합 서버/DB/웹 변경 전체. 이들은 통과로 추정하지 않는다.

## 의존성·빌드 이슈

- SDK 58의 일부 peer 요구가 맞지 않아 Expo 57.0.30/RN 0.86.3/React 19.2.3으로 고정했다. strict peer 검사를 끄지 않았다. 웹 React는 변경하지 않았다.
- Windows의 reparse-backed 파일에서 `readdir`의 Dirent와 `lstat` 판별이 달라 Metro가 실제 React 파일을 링크로 잘못 처리했다. 일반 크롤러와 fallback 양쪽에 Windows 한정 lstat 확인을 추가했다. 실제 링크를 보존하는 회귀 포함 4개 테스트 및 export가 통과했다. 재현 가능한 pnpm 패치를 저장했고 임시 패키지 사본은 정리했다.
- 임시 패치 작업 사본이 lint 대상에 들어가 첫 verify가 실패했다. 검사 규칙을 끄지 않고 사본만 제거해 재실행했다.
- `browserslist@4.29.3`의 아직 배포되지 않은 간접 의존 요구를 피하면서 보안 패치를 포함하는 4.28.7로 한정했고, xcode의 uuid는 11.1.1로 고정했다. lockfile과 정책 시험에 반영했다.

최종 의존성 감사에는 **high 2, moderate 1, 총 3건**이 남았다. 감사 종료 1을 성공으로 처리하지 않는다.

| 패키지 | 공지와 확인 결과 | 남은 조치 |
| --- | --- | --- |
| decode-uri-component | URI 디코딩 DoS. 감사 API가 >=0.4.3을 안내했지만 해당 버전은 registry에 없었고, 공식 공지의 0.5.0은 실제 존재/ESM | CommonJS query-string 경로와 API 호환을 시험한 뒤 교체. 단순 override로 강제하지 않음 |
| node-forge | RSA 서명 검증 high. 공식 공지는 수정 버전 없음, 감사 API의 1.4.1은 registry에 없음 | Expo 도구의 사용 경로·서명 검증 도달성 확인과 공급망 패치/교체 검토. 자체 암호 코드를 임의 수정하지 않음 |
| braces | 중첩 패턴 stack DoS high. 공식 공지는 수정 버전 없음, 감사 API의 3.0.4는 registry에 없음 | 외부 입력 도달성·도구 노출 제한과 상위 의존 교체/패치 검토 |

공식 공지: [decode-uri-component](https://github.com/advisories/GHSA-vcc3-ghjq-m6fr), [node-forge](https://github.com/advisories/GHSA-86w9-cpqp-85rv), [braces](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm). 감사 메타데이터의 수정 범위만 보고 존재하지 않는 패키지로 덮어쓰지 않는다. 현재 서비스에서 악용을 재현했다는 뜻은 아니지만 배포/실금융 베타 게이트는 열지 않는다.

## 최종 검증

- 모바일 43개 및 workspace 정책 5개: 종료 0.
- 모바일 타입 검사: 종료 0.
- Android export: 종료 0. APK/실기기는 미수행.
- 전체 `pnpm verify`: 종료 0. 린트·7 workspace 타입 검사·2,004개 테스트·API/웹 production build·Android 번들 통과. 구성은 legacy 208 + contracts 124 + database 단위 19 + API 318 + web 1,206 + mobile 43 + E2E preflight 86이다. 실제 DB 통합/브라우저 시험은 이 합계에 포함하지 않는다.
- PC Playwright 회귀: 18개, 48.4초, 종료 0. 실제 로컬 BFF/NestJS/폐기용 DB와 합성 인증을 사용했다. PC 편집·계정 격리·채널 권한·수집 설정 HTTP를 포함하며 Android 휴대폰 시험이 아니다. 첫 실행은 폐기용 DB 동의 환경변수 누락으로 안전하게 차단됐고, 고정 loopback 시험 설정 후 재실행했다.
- 전체 감사: 3건, 종료 1.
- `git diff --check`: 종료 0. Git 대상 821파일의 등록된 비밀 패턴 탐지 0건. 모든 종류의 비밀값 부재를 보증하는 검사는 아니다.
- 모바일 `.env`·`.env.local`·서명 키·Expo 캐시는 `git check-ignore`로 무시되는 것을 확인했다. `.env.example`에는 공개 테스트 origin 예시만 있다.

## 규모와 다음 순서

`apps/mobile` 신규 25파일(README 포함), 비어 있지 않은 줄 약 1,910줄이다. 제품·설정·테스트·문서 합산이며 제품 로직만의 크기가 아니다. 루트 변경은 package scripts, gitignore, workspace/lockfile, 정책 테스트 및 버전 고정 Metro 패치다. 이번 클라이언트 단위에서 API/DB/PC 제품 코드는 추가 수정하지 않았다.

1. 보안 공지 3건의 호환 교체/도달성 검증과 Android 개발환경 구축·APK 실행.
2. 실제 기기에서 합성 계정 로그인/조회/로그아웃, 계정 전환, 네트워크 단절, background/최근 앱, 키보드·접근성을 확인.
3. 수기 입력·계좌/카테고리 관리·조회 필터와 시각 계약을 작은 단위로 연결.
4. 지속 로그인 보강 후 명시적 동의/허용 출처/단일 수집 기기 정책을 갖춘 Android 알림 한 형식의 종단 흐름 구현.
5. 승인 범위의 중복·실패·규칙·이체/환불·복구·집계·PC 동기화 검증 후 iOS 착수.

혼합된 미커밋 작업은 보존한다. 이번 결과로 원격 PR 승인·운영 보안 감사·실기기 QA·실제 DB 이관을 완료 처리하지 않는다.
