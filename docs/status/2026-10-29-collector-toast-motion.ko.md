# 기기 지정 토스트 모션·카운트다운 개선

> 같은 날 후속 요청으로 진행 막대는 제거했다. 아래는 당시 구현/검증 기록이다. 현재 UI는 [중앙 확인 팝업·토스트 단순화](2026-10-29-collector-confirmation-dialog.ko.md)를 따른다.

## 요청과 범위

10/29 후속 요청으로 앞선 3초/전체 너비 토스트를 대체한다. 기존 알림 동의·대표 기기 지정 분리 작업은 보존한다.

- 아래에서 위로 220ms 동안 등장한다. 등장은 전체 표시 시간 2,500ms에 포함한다.
- 문구 너비에 좌우 20dp 여백을 더하고 가로 가운데에 배치한다. 화면보다 넓으면 줄바꿈한다.
- 버튼 반경 24dp에서 4를 뺀 20dp를 사용한다. Android에서는 CSS px 대신 논리 단위 dp다.
- 내부 막대가 남은 시간을 나타내며 2.5초 후 토스트가 사라진다. 서버 처리 진행률이 아니다.
- Android 애니메이션 줄이기/제거 설정에서는 등장 이동을 생략하고 막대를 단계적으로 갱신한다.
- 실패/새 작업/화면 이탈 때 기존 타이머 정리를 유지한다. 서버·DB·권한·로그인 정책은 변경하지 않는다.

## 변경 파일과 역할

1. `apps/mobile/src/ui/collector-toast.tsx` 신규: 크기, 정렬, 등장, 진행 막대와 시스템 모션 설정 처리.
2. `apps/mobile/src/ui/collector-screen.tsx`: 기존 인라인 토스트를 전용 컴포넌트로 연결.
3. `apps/mobile/src/collector/collector-settings.ts`: 제거 타이머와 UI가 공유하는 2,500ms 상수.
4. `apps/mobile/src/collector/collector-settings.test.ts`: 기존 시간 경계를 2,499/2,500ms로 변경. 새 UI 테스트 프레임워크는 추가하지 않음.
5. 본 문서, 기존 결과 문서의 후속 안내, 모바일 표면 브리프 및 DESIGN.md의 컴포넌트 기준 갱신.

작은 UI 수정이며 새 의존성/네이티브 APK 변경은 없다. 이 요청의 커밋·푸시는 별도 수행하지 않는다.

## 검증 계획

- 기존 타이머 시험을 먼저 실패시킨 뒤 구현한다. 오래된 타이머와 화면 종료 정리 회귀도 유지한다.
- 모바일 타입/린트/시험 및 Android 번들, 저장소 회귀와 PC Playwright.
- 연결 실기기의 합성 계정에서 등장, 너비, 막대 변화, 종료를 확인한다. OS 권한과 개인 금융 내역은 변경하지 않는다.
- 화면 검사는 최대 두 번의 묶음 점검으로 제한한다. 검증하지 못한 접근성/기기 조합은 완료로 표시하지 않는다.

## 진행

- 계획을 사용자와 노션 개발일지에 알리고 구현·검증했다.
- 최초 타이머 검증에서 예상대로 2건 실패/20건 통과를 확인했다. 2.5초로 구현 후 22건 모두 통과했다.
- 타입 검사에서 설치된 React Native의 제거된 `absoluteFillObject` 사용을 발견하고 실제 선언을 확인해 `absoluteFill`로 수정했다. 재검사 통과.

## 구현 설명

`CollectorSettings`가 성공 응답을 확인하면 문구를 게시하고 2,500ms 뒤 지운다. 새 작업/조회/화면 종료는 이전 타이머를 폐기한다. 이 상태를 `CollectorScreen`이 `CollectorToast`에 전달한다.

`CollectorToast`는 화면에 항상 연결되어 시스템 모션 설정을 미리 읽되 문구가 없으면 아무것도 그리지 않는다. 문구가 생기면 경과 시간을 기록하고 아래 24dp에서 제자리로 이동한다. 막대는 폭을 매 프레임 바꾸지 않고 잘린 영역 안에서 이동하여 줄어드는 효과를 낸다. 모션 설정이 도중 바뀌어도 시작 시간을 다시 잡지 않는다. 컴포넌트 종료/문구 변경 때 애니메이션과 단계 갱신 타이머를 정리한다. 진행 막대는 읽기 보조 도구에서 숨겨 수치가 반복 낭독되지 않게 하고 성공 문구는 polite live region으로 제공한다.

실기기 화면 녹화의 초기 프레임에서 토스트 상단 좌표가 위쪽으로 이동함을 확인했다. 스크린샷에서 막대가 긴 상태→짧은 상태→토스트 없음으로 바뀌었다. 녹화는 성공 응답과 같은 순간에 시작하지 않으므로 정확한 2,500ms 경계의 근거는 가상 시계 시험이다. 확인 후 합성 계정의 대표 기기를 원래 상태로 복구했고 Android 알림 권한/개인 거래는 변경하지 않았다.

자체 코드 점검에서 서버/DB/동의 정책 변경, 민감정보 표시, 종료 후 갱신 경로가 추가되지 않았음을 확인했다. 이번에 별도 독립 리뷰/보안 감사를 다시 수행한 것은 아니다. Impeccable 모션 지침으로 시스템 축소 모션 대응과 두 번 이내의 묶음 화면 검사를 적용했다.
