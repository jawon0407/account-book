# 2026-09-29 프로필·계좌·분류 웹 BFF

## 범위

`feature/bank-state-transitions` / HEAD `10ec214805d5b5fb9cb2ad7a8aceea43b2bd6ebe` 위의 미커밋 작업이다. 앞선 인증/스키마/API 변경을 보존했다. 이번에는 새 금융 API용 BFF 7경로·10동작만 추가했다. Next Node runtime이며 별도 DB 계정·마이그레이션·의존성 설치는 없다. PC 화면·은행·모바일 구현 완료로 표시하지 않는다.

파일별 범위는 [실행 계획](../superpowers/plans/2026-09-29-core-bff.md), 초급 개발자 설명은 [웹 BFF 가이드](../guides/core-bff-development.ko.md), 실제 테이블 존재 확인과 MCP는 [DB·브라우저 점검](2026-09-29-database-and-browser-check.ko.md)에 있다.

## 구현

- [x] 세션 쿠키 한 개·유효 형태·저장된 세션의 사용자만 신뢰. 제공자 토큰을 브라우저에 반환하지 않음.
- [x] POST/PATCH CSRF/Origin(부재 시 Referer)/Fetch Metadata. 기존 인증의 POST 전용 정책 유지.
- [x] 고정 내부 경로·scope·메서드, 엄격한 query/UUID/본문, 한 번 직렬화한 바이트 서명·전송.
- [x] 16 KiB 입력·1 MiB 출력·3초 JSON 읽기, gzip 등 압축 해제 후 실제 바이트 제한, 취소 처리.
- [x] 캐시·리다이렉트·자동 재시도 금지, 상류 헤더/비밀 필드 제외, 안전한 오류/상태 계약.

## 검증 및 리뷰

1. 작업 전 기존 웹 643개 통과.
2. 위임 fetch의 redirect/cache 정책과 새 CSRF 진입점이 없는 상태의 실패를 관찰하고 구현 후 관련96개 통과.
3. 새 컨트롤러의 최소 HTTP 경계에서 50개 실패를 관찰하고 구현했다. import 누락 실패와 기능 RED를 구분했다. 초기 테스트 fixture의 금액 문자열을 실제 계약인 숫자0으로 바로잡았다.
4. UUID 정규화 테스트 실패 후 수정. JSON 경계·7경로의 모든 HTTP 메서드를 실제 모듈에서 검사했다.
5. 독립 리뷰: Critical0, Important1(Next 내부 listener 주소와 공개 Origin 비교), 조건부 Minor1(압축 Content-Length와 해제된 바이트 비교). 둘 다 재현 테스트 3개 실패 확인 후 수정하여 통과. 같은 리뷰어가 수정분 재확인 후 남은 지적 없음.
6. 기존 인증 route-wiring 검사가 전체 실행에서 5초 timeout을 두 번 냈고 단독 실행은 1.66초로 통과했다. 첫 실행은 브라우저 컴파일과 겹쳤지만 브라우저 없이도 반복되었다. 원인은 timed test 안의 첫 모듈 로딩/변환을 함께 재는 구조였다. 두 import만 모듈 준비 단계로 이동했고 기존 assertions와 5초 제한은 그대로다. 최종 전체 결과는 아래 마감 기록에 적는다.
7. 최종 수정 후 Core/인증 route-wiring 집중 검사 145개 통과. 새 Core 129개이며 인증 기존16개는 별도다.
8. 공식 Playwright MCP의 격리 Edge에서 비로그인 `/api/profile`, `/api/accounts`, `/api/categories` 각각 401/AUTH_SESSION_EXPIRED와 private,no-store를 확인했다. OPTIONS405/CORS 비허용도 확인했다. 브라우저 콘솔의 401/405 오류4개는 이 의도적 거부 검사 결과이며, 가입 화면 자체 접속 당시에는 오류가 없었다.

## 최종 마감 기록

최종 `pnpm verify` exit 0: lint, 전체 typecheck, 일반 테스트 **1,380개**, API·웹 production build가 모두 통과했다. 합계는 legacy205 + contracts89 + database19 + API205 + web776 + E2E preflight86이다. 실제 브라우저 여정 테스트 수 또는 실제 DB suite 수로 혼동하지 않는다. 로그는 Git 제외 `output/core-bff-verify-final.log`다.

별도 웹 coverage 실행도 776개 통과했다. **기존 인증 보안 coverage 대상**의 branches828/828=100%, statements99.66%, lines99.72%다. 이 설정에는 신규 core BFF 파일이 포함되지 않으므로 “BFF 커버리지100%”라고 주장하지 않는다. `request-origin.ts`는 이 기존 보안 게이트에 포함되어 PATCH 확장 뒤에도 통과했다.

이번 추가/변경은 소스·테스트·문서 27개 파일 범위이며 기존 미커밋 변경 전체의 파일 수가 아니다. 새 서버 역할 파일은 28~83행, 테스트는 최대196행으로 분리했다. 전역 Codex MCP 등록과 Git 제외 진단 산출물은 이 소스 범위 밖이다.

Notion 12 카드에 DB 존재 확인·BFF 결과·테스트·제한·다음 UI 순서를 갱신했다. 상태는 진행 중/부분 구현·운영 미검증을 유지한다. 커밋·푸시·PR·배포·원격 금융 쓰기는 하지 않았다.
