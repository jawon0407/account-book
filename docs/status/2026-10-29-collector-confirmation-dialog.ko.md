# 기기 지정 중앙 확인 팝업·토스트 단순화

> 후속 요청으로 아래 완료 작업의 커밋·푸시가 승인됐다. 아래 미전송/미완료 실기기 기록은 작업 당시 이력이며, 전달 범위와 다음 단계는 [후속 정리](2026-10-29-notification-capture-next-steps.ko.md)를 따른다. 실기기 중단 항목을 완료로 바꾸지는 않는다.

## 요청과 선택

사용자의 10/29 후속 요청으로 토스트 진행 막대를 제거하고, 지정/교체/해제 확인 구역을 중앙 팝업으로 바꾼다. 알림 허용/거부에서 이미 쓰는 React Native `Alert`를 재사용한다. 별도 커스텀 모달은 스타일/접근성 구현을 중복하므로 추가하지 않는다.

- 토스트의 220ms 상향 등장, 문구 너비+좌우 20dp, 반경 20dp, 2.5초 종료는 유지한다.
- 기기 상태 카드 높이는 확인 팝업 때문에 늘어나지 않는다.
- 확인만 저장한다. 취소·Android 뒤로가기·바깥 닫기는 저장하지 않는다.
- 지정/교체/해제의 기존 경고 문구 및 동의·OS 재확인·기대 버전 검사는 유지한다.
- 이전 화면/계정의 팝업, 취소 후 새로 열린 팝업에 속하지 않는 콜백은 무시한다.

## 파일과 규모

제품 코드 3파일의 작은 UI/동작 연결 수정이다. `collector-toast.tsx`의 진행 막대·측정·시간 갱신 코드를 제거하고, `collector-screen.tsx`에서 중앙 Alert를 연다. `collector-enrollment.ts`는 팝업이 확인한 요청/화면/계정 경계에만 확인·취소를 적용하도록 콜백을 묶는다. 기존 `collector-enrollment.test.ts`에 해당 보호 검증을 보완한다. 새 UI 테스트 파일/의존성/서버/DB/네이티브 설정은 추가하지 않는다.

## 검증 계획

- 기존 모델 시험에 확인/취소, 중복 열기, 오래된 확인·취소, 계정/설치/세션/화면 변경 사례를 먼저 작성해 실패 확인 후 구현한다.
- 모바일 타입/린트와 전체 저장소 회귀, Android export, 기존 PC Playwright 흐름.
- 연결 실기기에서 지정/해제 팝업, 취소/뒤로가기/바깥 닫기, 확정 후 진행 막대 없는 토스트와 자동 종료를 확인한다. 합성 계정만 쓰고 OS 알림 권한은 바꾸지 않는다.
- 두 번 이내의 묶음 시각 검사. 전체 보안 감사나 독립 리뷰를 수행한 것으로 보고하지 않는다.

## 구현 및 검증 결과

진행 막대와 측정/갱신 코드를 제거했다. 지정·교체·해제는 기존 알림 허용/거부와 같은 중앙 `Alert`에서 확인한다. 토스트의 상향 등장과 2.5초 종료는 유지했다. 서버·DB·권한 계약은 바꾸지 않았다.

- 기존 모델 시험에 10개 보호 사례를 추가했다. 구현 전 10개 실패를 확인하고 구현 후 관련 55개가 모두 통과했다. 확인 전 쓰기 금지, 중복 확인, 취소 후 새 팝업, 계정/설치/세션/화면 변경 후 늦은 콜백을 검사한다.
- 전체 저장소 자동 테스트 2,377개 통과, 종료 코드 0: legacy 208, contracts 197, database 19, native 14, mobile 290, API 333, web 1,225, E2E 사전 점검 91. 실제 브라우저 E2E 2,377개를 실행했다는 의미는 아니다.
- 모바일 타입 검사, 변경 코드 린트, Android export, `git diff --check` 통과.
- 기존 PC Playwright의 로그인 → 내 계좌 → 새로고침 → 로그아웃 흐름 통과.
- 연결 Android 기기에서 지정/해제 중앙 팝업을 각각 확인했다. 해제 팝업의 취소 버튼 및 Android 뒤로가기는 닫힌 뒤 기존 지정 상태를 유지했다. 더 이상 카드 내부 확인 구역이 확장되지 않는다.

## 실기기 확인 한계 및 종료 상태

사용자가 테스트를 여기까지 마무리하도록 요청하여 추가 휴대폰 조작을 중단했다. 이번 수정본의 바깥 영역 닫기, 확인 후 지정/해제 성공, 진행 막대 없는 토스트의 실제 등장/종료는 실기기 미확인으로 남긴다. 2.5초 종료와 확인 콜백 보호는 자동 테스트로 검증했으며, 이전 버전의 토스트 영상은 이번 수정본 검증으로 대체하지 않는다.

사용자가 Android 알림 접근을 직접 허용한 뒤 마지막으로 확인한 화면은 ‘알림 여부: 허용됨’과 ‘이 기기가 지정되어 있어요’였다. 이 후속 검사에서는 확인 버튼을 눌러 지정/해제를 저장하지 않았으며, 종료 요청 후 권한·동의·기기 상태를 자동 변경하지 않았다. 실금융 알림 본문 수집은 여전히 구현되지 않았다. 테스트용 알림 접근은 필요 없으면 사용자가 Android 설정에서 다시 끌 수 있다.

전체 앱 보안 감사나 별도 독립 리뷰 완료를 주장하지 않는다. TalkBack, 큰 글꼴, 가로 화면, 다른 Android 기기의 이번 모달 검증은 별도다. 기존 미커밋 작업을 보존했으며 이번 작업을 커밋·푸시하지 않았다.
