## 아직 확인하지 않은 것

- 로그인 API 성공, 장부 목록 조회, 수기 거래 저장, PC와 같은 기록 확인.
- 통신 끊김·복귀, 앱 재실행, 큰 글자/TalkBack, 최근 앱 미리보기 등 전체 실기기 검증.

## 로그인 서버 연결의 현재 경계

Metro 시작 프로세스에 공개 API origin `https://localhost:3000`을 지정해 기존 로그인 화면을 실행했다. 이 주소는 **접속 성공 증거가 아니라 로컬 개발 대상 주소**다. 모바일 `.env`나 제품 코드는 바꾸지 않았다.

점검 시 PC 3000/3001 포트에 로그인용 서버가 실행 중이지 않았다. 3000 포트의 USB 연결도 만들지 않았다. 휴대폰에서 신뢰할 HTTPS 인증서와 테스트 BFF/API 구성은 다음 단계다. PC에서 localhost 인증서를 신뢰했다고 Android 앱이 같은 인증서를 신뢰하는 것은 아니다.

실제 계정 비밀번호·거래 정보 입력이나 운영 DB 변경은 하지 않았다. 휴대폰 인증서 추가, TLS 검증 해제, HTTP 금융 API 전환, 클라우드 배포도 하지 않았다. 다음 연결 작업에서는 테스트용 데이터로 서버·인증서 신뢰를 별도로 확인해야 한다.

## 이번에 만난 환경 문제

1. 제한된 실행 환경에서 ADB 서버 시작 실패 → 호스트 권한으로 실행한 ADB는 정상 시작하고 승인된 기기 한 대를 확인했다. 첫 실패를 ‘휴대폰 미연결’로 판단하지 않았다.
2. 최초 Metro는 `localhost`를 IPv6 `::1`에만 바인딩했다. 이 작업이 시작한 프로세스만 확인 후 종료하고 Node의 `--dns-result-order=ipv4first`로 다시 실행했다. 최종 `127.0.0.1` 응답과 휴대폰의 실제 번들 로드를 확인했다.
3. 새 개발 앱의 첫 실행 안내가 화면을 덮고 있어 Continue와 Close를 순서대로 선택했다. 제품 화면 결함으로 오인하지 않았다.

## 작업 범위·증거

- 제품 코드·의존성·APK 변경 없음. 이번 추가 산출물은 이 상태 문서와 실기기 안내 갱신이며, Notion 07에도 같은 완료/미완료 경계를 기록한다.
- 로컬 로그/화면 증거: Git 제외 경로 `output/android-device-2026-10-20/`. 화면 캡처는 Account Book이 앞에 있을 때만 수행했고 다른 앱·메시지는 읽지 않았다. 기기 화면은 Notion이나 GitHub에 업로드하지 않는다.
- 이 실행 확인에서는 테스트 코드나 PC 웹을 수정하지 않았고 전체 시험·Playwright를 다시 돌리지 않았다. 10월 19일 110개 시험 결과와 오늘의 실기기 확인을 구분한다.
- 커밋·푸시·배포 없음. 테스트가 끝나면 USB 디버깅을 끄고 사용자가 잠시 해제한 보안 위험 자동 차단을 다시 켠다.
