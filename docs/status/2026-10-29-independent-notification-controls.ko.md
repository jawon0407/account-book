# 알림 허용·거부와 대표 기기 지정 분리

> 후속 변경: 아래 3초/전체 너비 토스트 기록은 최초 구현 결과다. 같은 날 2.5초·내용 너비·등장 모션으로 개선한 뒤 진행 막대를 제거했다. 현재 기준은 [중앙 확인 팝업·토스트 단순화](2026-10-29-collector-confirmation-dialog.ko.md)를 따른다. 후속 커밋·푸시 승인과 다음 개발 범위는 [전달·다음 단계](2026-10-29-notification-capture-next-steps.ko.md)에 기록한다.

## 요청 및 설계

사용자의 10/29 요청을 기준으로 앞선 자동 기기 지정 설계를 대체한다. 여러 기기 로그인과 계정당 수집 기기 1대 정책은 그대로다.

- ‘동의 철회 안내’, ‘Android 알림 접근 관리’ 독립 버튼을 제거한다.
- 실제 허용이 확인되면 기존 파란 ‘알림 허용’을 빨간 ‘알림 거부’로 전환한다. 거부 팝업 확인 후 서버 동의를 철회하고 OS 접근이 켜져 있으면 Android 설정을 연다. OS 스위치는 사용자가 직접 끈다. 조회/철회 실패를 성공으로 표시하지 않는다.
- 동의만 남거나 OS 상태만 확인되는 복구 상황에도 철회 경로를 없애지 않는다. 허용 팝업 안에 거부 선택지를 제공하거나 같은 버튼을 ‘권한 확인’으로 사용한다. 별도 큰 관리 버튼을 다시 추가하지 않는다.
- 알림 허용/설정 복귀는 대표 기기를 지정하지 않는다. 별도 ‘이 기기 지정’/‘이 기기로 변경’에서 확인한 경우에만 지정하며, 확정 직전에 동의·OS 접근을 재검사한다. 없으면 허용부터 안내하고 자동 재개하지 않는다.
- 알림 거부는 대표 기기를 임의 변경하지 않는다. 지정 여부와 별개로 동의가 없으면 수집할 수 없다는 기존 서버 계약을 유지한다.
- 지정 성공의 고정 문구 대신 ‘기기 지정을 완료했습니다.’를 3초간 하단 비조작 알림으로 표시한다. 해제 성공은 ‘기기 지정을 해제했습니다.’. 성공 응답 전/실패/화면 종료 후에는 표시하지 않는다. 상단과 상세 설명의 실제 수집 미구현 고지는 유지한다.

## 접근 방법과 규모

기존 동의/기기 API를 분리해서 호출하는 방법을 채택한다. 서버와 DB에 새 통합 토글을 만들면 범위와 실패 조합만 늘어나므로 하지 않는다. UI에서 문구만 바꾸는 방법은 기존 자동 지정 동작이 남으므로 적합하지 않다.

중간 규모: 제품 7파일, 기존 시험 3파일, 계획/결과/표면 문서 3파일을 다룬다. 새 의존성, 네이티브 APK, DB 마이그레이션, 로그인 정책 변경은 없다. 사용자의 기존 반복 승인 생략 요청에 따라 계획을 먼저 알리고 같은 작업에서 구현·검증했다. 이 요청에서는 새 커밋·푸시를 자동 수행하지 않는다.

## 검증 계획

- 실패 시험부터: 허용/OS 왕복이 지정 API를 호출하지 않음, 별도 지정/교체/취소, 권한 철회·계정 전환·늦은 팝업·중복 탭, OS 설정 실패/서버 철회 실패, 토스트 2,999ms 유지·3,000ms 제거·화면 종료 정리.
- 모바일 전체 시험, 타입 검사 2종, 변경 파일 lint, 전체 저장소 회귀, Android 번들, PC Playwright.
- 연결된 기기는 합성 계정만 사용해 화면·거부/지정 분리·토스트를 확인한다. OS 스위치를 자동 조작하지 않으며 연결 불가나 사용자의 직접 조작이 필요한 경우 미검증 항목을 구분한다.
- 독립 코드 리뷰와 노션 결과 기록. 실제 금융 알림 수집 완성으로 보고하지 않는다.

## 진행 기록

- 계획과 변경 파일을 먼저 알리고 노션 개발일지에 착수 내용을 기록했다.
- [노션 개발일지](https://app.notion.com/p/407323168ba6815187d1c47ed95c9de2)에 10/29 결과 추가 저장 성공을 확인했다.
- 최초 목표 시험은 27건 실패/52건 통과를 확인한 뒤 구현했다. 최종 관련 시험은 84건 모두 통과했다.
- 독립 리뷰에서 중요도 Important 1건을 발견했다. 동의를 철회하고도 OS 접근이 남은 상태에서 재동의 없이 설정으로 돌아갈 경로가 없었다. 기존 허용 팝업에 ‘권한 해제 설정’을 넣었다. 이 선택은 동의/기기 변경 API를 호출하지 않는다. 3건 실패 재현 후 추가 회귀 시험 5건과 실기기 설정 왕복으로 보완을 확인했다. Critical 및 다른 Important/Minor 발견은 없었다. 수정 후 별도 재리뷰를 통과했다고 주장하지 않는다.

## 구현 흐름과 역할

1. `notification-consent-copy.ts`가 서버 동의와 OS 상태로 표시/버튼 정책을 계산한다. 양쪽 모두 확인돼야 ‘허용됨’과 빨간 ‘알림 거부’가 나온다. 서버 장애를 거부 성공으로 오인하지 않도록 ‘권한 확인’과 팝업 내부 복구 선택지를 유지한다.
2. `notification-access-panel.tsx`는 큰 관리 버튼 두 개를 제거하고 ‘자세히 알아보기 / 허용 또는 거부’ 두 칸만 사용한다. 팝업 취소에는 변경이 없다. 거부 확인은 서버 동의를 철회하고 필요 시 Android 설정으로 이동한다.
3. `collector-enrollment.ts`에서 허용 후 자동 지정하던 임시 의도/복귀 로직을 제거했다. 허용은 동의 API만, 별도 지정 확인은 기기 API만 호출한다. 지정 확정 직전에 동의와 OS 접근을 다시 확인하고, 화면·계정·설치·세션 세대가 바뀐 오래된 팝업 응답은 버린다.
4. `collector-settings.ts`가 지정 성공 후 토스트를 3,000ms 관리한다. 새 작업·새로고침·화면 종료 때 이전 타이머를 정리한다. 실패하거나 응답을 잃은 경우 후속 조회에서 지정이 보여도 성공 토스트를 만들지 않는다.
5. `collector-screen.tsx`는 ‘이 기기 지정 / 이 기기로 변경 / 기기 지정 해제’를 독립적으로 제공하고, 비조작 토스트를 스크롤 밖 하단에 표시한다. 성공 문구의 ‘준비 중’은 삭제하되, 아직 수집하지 않는다는 상단/도움말 고지는 유지한다.

실기기에서 확인한 항목:

- 빨간 거부 버튼, 제거된 관리 버튼 두 개, 고정 성공 문구 제거.

- 지정 해제 후 알림 동의를 다시 허용해도 ‘지정된 기기 없음’ 유지. 별도 ‘이 기기 지정’ 확인으로만 지정됨.

- 최종 합성 계정 상태는 테스트 전과 같은 허용/이 기기 지정. OS 권한 스위치와 개인 거래는 변경하지 않음.

## 범위와 남은 점

- 실제 금융 알림 수집/파싱/자동 거래 저장은 이번 작업 범위가 아니다.
- 실제 Android 권한 해제는 사용자가 설정에서 직접 해야 한다. 서버 동의 철회와 OS 스위치는 동일한 작업이 아니다.
- 이번 화면 시각 검증은 연결된 세로 화면/현재 글자 크기다. TalkBack, 가로 화면, 다른 제조사·태블릿, 이번 수정의 큰 글꼴 전체 흐름은 미검증이다.
- 전체 보안 감사·의존성 취약점 재검사·운영 DB 통합 시험을 새로 수행한 것은 아니다. 이번 리뷰는 변경 코드의 상태/권한 경계와 토스트 수명 관리에 한정한다.
- 기능 브랜치 `feature/bank-state-transitions`, 기준 `b6da387`. 이번 변경은 커밋·푸시·병합하지 않았다.
