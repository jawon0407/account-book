# 알림 허용과 수집 기기 지정 연결

## 승인된 범위

여러 기기 로그인과 장부 공유는 유지한다. 알림 허용 팝업에서 사용자가 동의한 경우에만 서버 동의 → Android 접근 확인 → 수집 기기 지정으로 연결한다. 기존 기기가 있다면 교체 확인을 한 번 더 받는다. 실제 알림 본문 수집/분류/업로드는 이번 범위가 아니다. 사용자는 실기기 검증·독립 리뷰·커밋·푸시를 승인했다.

## 변경 파일과 규모

- 신규: `apps/mobile/src/collector/collector-enrollment.ts`, 같은 이름의 `.test.ts` — 기존 동의/기기 모델을 조합하는 흐름과 회귀 시험.
- 기존: `notification-access.ts` — OS 설정 이동 결과를 호출자에게 반환.
- 기존: `notification-consent-copy.ts`, `.test.ts` — 독립 리뷰에서 확인된 거절 표시 우선순위 보완.
- 기존: `apps/mobile/app/index.tsx`, `src/ui/ledger-flow.tsx` — OS 설정 왕복 동안 메모리에만 명시적 사용자 의도를 유지. 계정/설치/세션이 바뀌면 폐기.
- 기존: `collector-screen.tsx`, `notification-access-panel.tsx`, `notification-access-guide.tsx`, `collector-copy.ts` — 별도 지정 버튼을 허용 흐름으로 통합하고 안내 갱신.
- 문서: 상태 보고서와 기존 화면 설계 기록 갱신. Notion 개발일지에 진행/검증/한계를 기록.
- 예상 제품 코드 250~400줄, 시험 250~400줄 추가·수정. 서버·DB·로그인 정책·네이티브 모듈·의존성은 변경하지 않는다.

## 안전 계약

1. 화면 진입·새로고침·프로세스 재시작만으로 지정 요청을 보내지 않는다.
2. 설정 왕복 의도는 메모리에만 10분 보관한다. 계정/서버/설치/로그인 세대 변경, 시간 역행, 만료 시 폐기한다.
3. 동의와 OS 접근을 새로 조회하여 둘 다 확인된 경우만 지정한다. 거절/실패/취소는 기존 기기를 바꾸지 않는다.
4. 다른 기기는 명시적 교체 확인 후 지정한다. 확인 직전 동의/권한을 재검증하며 서버 버전 충돌 시 자동 반복하지 않는다.
5. 지정 해제와 동의 철회는 권한 허용 없이도 가능해야 한다. 화면을 명시적으로 떠나거나 철회하면 미완료 지정 의도를 취소한다.
6. 서버 요청 결과가 불확실하면 조회만 하고 쓰기를 재전송하지 않는다. 여러 로그인 유지 및 서버의 계정당 1대 검사를 재사용한다.
7. ‘허용됨’은 동의+OS 접근 상태이지 실제 알림 수집 중이라는 뜻이 아니다.
