# 알림 설정 재조회·상세 안내 정리 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. 사용자 요청에 따라 직접 진행하고, 간단한 구조/UI 수정에는 새 테스트 코드를 추가하지 않는다.

**Goal:** 승인된 3·4번 및 후속 1번 요청을 반영해 상태·재조회 버튼을 각각 하나로 합치고 상세 안내를 팝업으로 제공한다.

**Architecture:** 기존 CollectorSettings와 NotificationAccess 모델은 유지한다. 두 모델의 화면 수명을 CollectorScreen에서 관리하고 재조회한다. 안내 팝업은 표시 상태만 가지며 동의/API/OS 변경을 하지 않는다.

**Tech Stack:** 기존 React Native·Expo·TypeScript. 의존성 추가 없음.

**Spec:** 아래 사용자 확정 사항과 화면 계약이 이번 소규모 변경의 설계다.

## 사용자 확정 사항과 범위

- 2026-10-28 최초: 1번은 ‘계정·설치의 동의’ 문구의 의미 질문이었다. 이후 사용자가 두 상태 대신 ‘알림 여부: 허용됨/허용되지 않음’으로 통합 표시를 명시적으로 요청했다.
- 서버의 최신 동의와 Android 접근이 모두 확인되었을 때만 ‘허용됨’. 동의 미수락/철회/고지 변경 또는 OS 거절은 ‘허용되지 않음’. 조회/저장 중은 ‘확인 중’, 오류/응답 없음/네이티브 미지원은 ‘확인 필요’로 구분한다. 내부 권한·행동 정책은 유지하고, 서비스 연결 세부 표시만 숨긴다.
- 3번: 큰 재조회 버튼 2개 대신 화면 상단의 작은 재조회 버튼 1개. Android 설정 복귀 시 기존 세션 재검증·상태 재조회 유지.
- 4번: 소개 문단 옆의 작고 둥근 ‘자세히 알아보기’ 버튼으로 상세 안내 팝업을 연다. 하단의 긴 안내 구역은 제거한다.
- 별도 승인된 후속: 여러 기기 로그인 유지, 자동 수집 기기만 계정당 1대. ‘알림 허용’ 과정에서 동의·OS 권한을 확인한 뒤 수집 기기를 설정하고, 다른 기기에서 옮길 때는 명시적으로 확인한다. 이번 UI 정리에서 이 연결이 완료됐다고 표시하지 않는다.

## Approaches

- 큰 버튼 삭제만: 단순하지만 서버/OS 상태 재조회와 오류 복구가 덜 명확하다.
- 상단의 작은 통합 재조회: 사용자가 수락한 방향. 기존 모델의 GET 재조회만 사용한다.
- 개발용 톱니바퀴 위 고정 버튼: Expo 개발 도구와 제품 UI를 결합하게 되어 채택하지 않는다. 정식 앱 화면의 상단에 둔다.

## Global Constraints

- 기존 Bookify 색·폰트·최소 48dp 조작 영역을 유지한다. 작은 도움말 텍스트도 14sp를 유지한다.
- 알림 원문 수집·분석·전송은 미구현이며 완료로 표시하지 않는다.
- 동의 철회와 OS 접근 관리 경로를 유지한다. 재조회/안내 열기는 동의나 권한을 바꾸지 않는다.
- ‘자세히 알아보기’는 설명만 표시한다. 실제 선택 동의 팝업은 기존 알림 허용에 남긴다.
- 로그인·DB·API·Kotlin·의존성·PC 제품 코드 변경 없음. 커밋·푸시 없음.
- 기존 미커밋 작업 보존. 레이아웃만의 테스트 코드는 추가하지 않는다. 후속 통합 상태 판정은 기존 테스트에 12사례를 추가해 미수락/철회/고지 변경/OS 거절/조회 오류를 검증한다.

## Review Focus

1. 조회/저장 중 재조회 중복 탭은 두 모델의 상태를 덮어쓰지 않아야 한다.
2. 설정 앱 왕복/백그라운드 때 모델은 종료되고 복귀 후 다시 조회되어야 한다.
3. 팝업에서 Android 뒤로가기를 누르면 팝업만 닫히고 장부로 이동하면 안 된다.
4. 긴 안내·큰 글꼴에서 내용은 스크롤되고 닫기 버튼을 찾을 수 있어야 한다.
5. 안내 열기/닫기와 재조회는 동의/지정/OS 권한을 변경하지 않아야 한다.
