# PC Core Web Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 로그인 이후 본인 프로필·계좌·카테고리를 실제 API로 관리한다.
**Architecture:** 경로별 React 화면, 사용자별 QueryClient, 계약 검증 ky 요청을 분리한다. DB/API 기존 구현은 재사용한다.
**Tech Stack:** TypeScript, Next 16, React 19, ky 2, TanStack Query 5, Zod 4, Vitest, Playwright.
**Spec:** `docs/superpowers/specs/2026-09-30-core-web-design.md`

## Global Constraints

- 기존 dirty worktree 변경을 보존. 새 의존성/DB migration 없음. 커밋/푸시는 별도 요청 시 진행.
- Node 22.15.1 / pnpm 11.9.0으로 검증. hosted DB에 합성 금융정보 쓰기 금지.
- 기존 인증 UI 유지. 한국어 함수 설명/매개변수 주석 포함. PC 웹은 반드시 실제 Playwright 실행.

## Review Focus

1. 요청 완료 여부를 모르는 생성 재시도는 중복을 만들지 않는다 — Task 1/2 테스트.
2. 사용자 변경·로그아웃 후 이전 캐시가 다시 나타나지 않는다 — Task 2/3 테스트.
3. 다른 기기에서 수정한 레코드를 오래된 버전으로 덮어쓰지 않는다 — Task 2/3 충돌 테스트.
4. 보관 필터·긴 이름·빈 목록·음수 금액을 정확하게 표시한다 — Task 2/3 테스트.
5. 잘못된 응답과 네트워크 오류에 성공 안내나 원본 오류를 표시하지 않는다 — Task 1/3 테스트.

**Interfaces:** `createLedgerApi(http?, expectedUserId?)`는 profile/get/update 및 accounts/categories list/create/update/archive. `coreKeys(userId)`는 사용자별 캐시 키. `createIntent()`는 정규화 payload별 UUID를 유지.

## 실행 기록

- 2026-09-30: 사용자 요청에 따라 반복 승인 없이 진행. 기존 Figma 승인안 재사용, 새 디자인 시안/브랜치/DB 변경 없음. 역할별 분리 약 20~25개 파일 예상(테스트·문서 포함 시 증가 가능).
- 독립 리뷰 후 `server/core/core-controller.ts`와 검사에 계정 일치 조건 추가. 읽기·수정·생성의 잘못된 사용자 요청은 Nest 전송 전에 거부한다. 프로필 늦은 응답과 로그아웃 중 조기 이동도 RED→GREEN 보완.
- 테스트 실행기는 서버 종료 이후 DB 정리를 위해 별도 `core/run.ts`로 분리했다. `.gitignore`에 생성 HTTPS 인증서와 Playwright 결과를 제외했다.
- 문서 스킬은 기존 docs 관례에 맞춘 사용법·설명·증거 문서 작성에 사용한다. Windows에서 POSIX 전역 설정/텔레메트리 부트스트랩은 실행하지 않으며 별도 커밋·푸시·스킬 설정 변경은 범위 밖이다. 기준 원격은 GitHub, 기본 브랜치는 main이다.
