# Bank API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans task-by-task. Steps use checkbox syntax.

**Goal:** A1/A2를 안전한 Nest HTTP 경계에 연결하고 가상 공급자로 검증한다.
**Architecture:** DB 실행기/저장소 → 서비스+공급자 port → 별도 공개 Callback/보호 컨트롤러. 기본 비활성.
**Tech Stack:** NestJS/Fastify, TypeScript, pg, Zod, Vitest/PostgreSQL17. 새 의존성 없음.
**Spec:** docs/superpowers/specs/2026-10-02-bank-api-design.md

## Global Constraints

- 서버 principal만 소유자로 사용. quota와 claim은 공급자 동작 전 별도 commit. 외부 호출 DB transaction 밖.
- fake/test만, live 차단, 기본 런타임 서비스 null. 공식 URL/키/운영 DB/커밋·푸시 변경 없음.
- start300초5회/Callback60초60회. callback code4096bytes/error128bytes. 교환8초 AbortSignal.
- 실패·성공 no-store/no-referrer. 토큰은 암호화 저장, 공개 상태2필드만. 한국어 설명·Notion 기록.

## Review Focus

- quota 소비 후 후속 DB 작업 실패가 횟수를 되돌리지 않는가(Task1).
- claim commit 실패/중복 완료가 공급자 교환을 다시 실행하지 않는가(Task2).
- timeout 뒤 늦게 온 성공 응답이 연결을 저장하지 않는가(Task2).
- Callback 중복 query/공격자 forward header/결과 URL에 민감값이 섞이지 않는가(Task3).
- JWT body/scope/replay 검사와 기본 비활성이 신규 경로에도 적용되는가(Task3).
