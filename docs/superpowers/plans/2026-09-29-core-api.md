# Core API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans; tasks use RED→GREEN with one final independent review.

**Goal:** 프로필·계좌·카테고리 NestJS API를 실제 SQL 저장 계층에 연결한다.
**Architecture:** 기존 MeModule 풀/AuthGuard 공유, 기능별 repository, user-scoped SQL transaction, strict Zod HTTP 계약.
**Tech Stack:** Node.js 22, NestJS 11/Fastify 5, pg, Zod 4, PostgreSQL 17, Vitest.
**Spec:** `docs/superpowers/specs/2026-09-29-core-api-design.md`

## Global Constraints

- 기존 인증 및 미커밋 DB 변경 보존. 새 migration/원격 금융 기록/푸시 없음.
- nickname 1~50자 또는 NULL, expectedVersion 양의 안전 정수. 프로필 role/provider/deletion/avatar 쓰기 제외.
- 동일 API 풀 max5, 사용자 UUID는 principal만. statement 5초/lock 1초/idle transaction 5초.
- 계좌/카테고리 기존 strict 계약, 생성 멱등성, 수정 version, hard delete 없음, 목록 최대1000 초과는 오류.
- 기능 코드마다 한국어 동작/인수 주석. 상세 가이드와 Notion02/12 기록.
- 사용자의 반복 승인 생략 요청에 따라 설계·파일 계획을 공개하고 같은 세션에서 직접 실행. 이전 미커밋 의존성으로 커밋은 별도 정리.

## Review Focus

- 악성 role/owner/provider 및 query 배열 → strict 계약/본인 경계 거부 (Task1/3).
- DB rollback 실패나 pooled context 잔류 → 연결 폐기/다음 사용자 격리 (Task2).
- 같은 요청의 동시 생성·응답 유실·키 대소문자 → 한 행/최초 snapshot (Task2).
- bigint SUM overflow·삭제/이체/시작 잔액 → 정확한 합계 또는 고정503 (Task2).
- 타 사용자 자원·보관된 수정·동시 version →404/409, 타인 존재 미노출 (Task2/3).
