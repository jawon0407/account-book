# Android 알림 출처 선택 저장 — 첫 구현 범위

> **대체된 설계(2026-10-28):** 사용자 요청으로 고정 5종 목록과 선택 저장 구현은 제거한다. 현재 설계는 [알림 허용 단일 진입점](../plans/2026-10-28-notification-permission-entry.md)이다. 아래는 당시 구현·검증 이력이며 현재 기능으로 해석하지 않는다.

## 목적과 근거

Notion 02의 사용자가 선택한 출처만 수집한다는 승인 요구사항을 구현하기 위한 첫 단위다. 사용자는 추가 승인 반복 없이 기존 문서를 따라 진행하도록 요청했다. 이번 상세 저장 방식은 개발자의 선택이며 사용자가 별도로 선택한 것으로 기록하지 않는다.

실기기에서 서버 동의 철회(version 6)와 Android 알림 접근 해제를 확인했고, 읽기 전용 재조회 후에도 유지됐다. 앞선 추가 동의는 사용자가 직접 켠 것으로 확인됐다.

## 방식 비교와 선택

- 기기 안에서 계정별 선택 저장: 실제 수집 기기 1대 정책에 맞고 서버·DB 변경 없이 최소 개인정보로 구현 가능. 기기 변경 시 다시 선택해야 한다. 이번에 선택한 방식이다.
- 서버에서 출처 설정 동기화: 다른 기기로 설정을 가져올 수 있지만 설치된 앱·권한이 기기별로 달라 추가 검증과 DB/API 계약이 필요하다. 후속 필요가 생기면 검토한다.

## 계약

- 이번 준비 목록은 KB스타뱅킹, 카카오뱅크, 토스, 카카오톡, 문자 앱이다. 제품의 최종 지원 은행 제한이 아니라 단계적 구현 목록이다. 미지원 금융 앱은 수기 사용을 유지한다.
- 새 계정의 기본 선택은 없음. 복수 선택과 전체 해제 가능. 토글은 화면 초안만 바꾸고 ‘출처 선택 저장’을 눌러야 저장된다. 저장하지 않고 화면을 나가면 초안은 버린다.
- 선택은 서버 origin·사용자 ID·설치 ID에 묶어 OS 보안 저장소에 저장한다. SHA-256 키 이름을 사용하고 금융 원문·거래·비밀 토큰을 저장하지 않는다. 계정 변경·로그아웃 시 이전 응답을 표시하지 않는다.
- 읽기/쓰기 오류는 일반 안내와 재조회 경로를 제공한다. 원문 오류를 노출하지 않는다. 잘못된 형식·미지 버전은 빈 선택으로 조용히 덮어쓰지 않는다.
- 선택 저장과 동의·OS 권한·기기 지정은 독립이다. 동의가 철회되어도 준비 선택은 관리 가능하며, 저장이 동의나 시작을 뜻하지 않는다.
- 앱 재실행 후 같은 계정·설치의 저장 선택을 복원한다. 다른 계정에는 노출하지 않는다. 저장 중 중복 요청이나 종료 후 늦은 응답은 현재 화면에 영향을 주지 않는다.

## 화면

기존 Bookify 색상·글자·스크롤·최소 48dp 동작 영역을 유지한다. 기존 동의 패널 아래 별도 ‘알림 출처 선택’ 섹션을 추가한다. 복수 선택 행은 체크박스 역할과 선택 상태를 읽어 주며, 명시적 저장 버튼과 현재 저장/변경 상태를 함께 표시한다.

‘이 기기의 현재 계정에 선택만 저장해요. 실제 알림 수집은 아직 시작되지 않아요.’를 분명히 표시한다. 실행하지 않는 시작/중지 버튼이나 수집 중 배지는 추가하지 않는다.

## 범위 밖과 후속

실제 패키지 검색·본문 접근·파서·자동 거래 업로드·백그라운드 작업·서버 수집 시작/중지·원문 재전송 큐·DB migration·PC 화면 변경은 이번 첫 단위에 포함하지 않는다. 다음 단위에서 시작/중지 상태와 네이티브 처리 연결을 별도 검증한다. 네이티브 코드를 바꾸기 전 Windows 빌드 경로 문제도 해결해야 한다.

## 완료 조건

기본 없음, 선택 저장/복원/해제, 계정·서버·설치별 격리, 잘못된 저장 데이터, 저장 실패, 화면 종료·계정 전환 뒤 늦은 응답을 테스트한다. 전체 기본 테스트·모바일 타입 검사·PC Playwright 회귀와 실기기 화면 확인을 실시하고 실제 수집 미구현 범위를 기록한다.
