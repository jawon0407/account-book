# Android 수기 입력·거주 기준 연결 설계

2026-10-16. 기존 승인된 개인 장부 정책과 Notion 07의 다음 단위를 구현한다. 사용자가 반복 승인을 생략하고 진행하도록 지시한 범위 안에서 작성한다. 새로운 사업/권한/배포 결정을 포함하지 않는다.

## 목적과 범위

Android에서 알림이 없는 거래를 사용자가 직접 기록하고 같은 서버 장부·PC에서 확인한다. 금액과 수입/지출, 날짜는 필수다. 계좌·카테고리·거래 상대명·메모는 선택이다. 자동분류 설정을 강제하지 않는다. PC 신규 작성 제한을 유지한다.

순서: (1) 모바일 API/인증 경계 (2) 입력·시각·저장 상태 모델 (3) Android 화면 (4) 통합·보안·리뷰. 이번 문서는 전체 순서를 유지하며 일부 단계의 통과를 화면/앱 전체 완료라고 쓰지 않는다.

## 대안과 선택

- 선택: 기존 native BFF의 프로필·참조 목록·거래 생성 API를 재사용한다. 서버 소유권/RLS/멱등 규칙을 공유하고 단일 DB를 유지한다.
- 앱에서 Supabase 직접 쓰기: 기존 세션·최소 권한과 다른 보안 경계가 필요하므로 채택하지 않는다.
- 로컬 금융 대기열/자동 재전송: 사용자 승인 정책과 다르므로 채택하지 않는다. 명시적 재시도만 한다.

## API와 인증

`NativeClient.ledger`는 고정 profile/accounts/categories/transactions 경로만 제공한다. strict 공용 입력/응답 schema, HTTPS·쿠키 미사용·리디렉션 거부·10초 제한·자동 retry0을 그대로 적용한다. UI가 토큰이나 경로를 지정하지 않는다.

SessionManager의 profile/updateProfile/accounts/categories/createTransaction 메서드는 기존 목록 조회와 같은 인증 guard를 쓴다. 토큰 갱신은 직렬화하고 본문 요청을 자동 재전송하지 않는다. 로그아웃/다른 계정/foreground 검증 중 늦은 응답을 UI에 반환하지 않는다. profile 응답 id도 현재 인증 사용자와 일치해야 한다. 프로필 수정은 expectedVersion을 필수로 보내 충돌 시 재조회한다.

## 입력과 시각

원화 양의 안전 정수만 허용한다. 소수·음수·0·지수 표기는 거부하며 쉼표는 올바른 천 단위 표기일 때만 제거한다. 수입/지출을 바꾸면 다른 종류의 카테고리는 해제한다. 보관된 참조를 새 기록에 사용할 수 없다.

거주 기준은 명시적으로 선택한다. 기기 시간대는 제안만 하고 자동 저장하지 않는다. 여행 중 기기 설정으로 장부 기준을 바꾸지 않는다. 날짜만 알면 시각 없이 저장한다. 시각 입력은 날짜+HH:mm+명시 시간대에서 UTC로 변환하며 DST 존재하지 않는 시각은 거부, 중복 시각은 선택하도록 한다. 당시 거주 기준/이사 경계의 최종 판단은 기존 서버가 한다. 시각을 임의 자정으로 채우지 않는다.

## 저장 상태

한 저장 시도에서 검증된 payload와 UUID 멱등 키를 고정한다. 중복 탭은 단일 요청으로 합친다. 성공 응답을 받으면 완료로 전환하고 목록을 다시 읽는다. 네트워크/응답 판독/5xx 등 결과 불명은 동일 payload/키로만 사용자가 재시도한다. 이때 필드 수정·새 키 생성으로 조용히 재전송하지 않는다. 명시적으로 편집으로 돌아가려면 저장 가능성 안내와 목록 확인이 필요하다.

화면 background/재검증 동안 같은 계정의 미완료 시도는 메모리에 유지하되 화면은 가린다. 계정 전환/로그아웃 때 폐기한다. 디스크 금융 캐시·장기 자동 전송 큐는 만들지 않는다. 프로세스 종료 후에는 저장 목록을 먼저 확인하라는 안내가 필요하다. 실제 알림 실패 최소 표식 계약은 별도 과제다.

## 화면과 검증

기존 Bookify 토큰과 Android 48dp 터치 영역을 재사용한다. 단일 수기 입력 흐름에 금액/방향, 날짜/선택 시각, 선택 계좌/분류, 상대/메모를 배치한다. 미설정/불러오는 중/빈 참조/오류/충돌/결과 불명/성공을 구분한다. 이미 작성한 화면에서 새 계좌·카테고리 관리로 확장하는 것은 후속 단위다.

테스트는 실제 NativeClient HTTP 경계, SessionManager 계정 격리, 순수 입력·시각 함수, 저장 상태 전이, 기존 서버/PC 통합을 포함한다. JS 번들은 APK/실기기 검증이 아니며 키보드·Back·글자 확대·TalkBack·기기 tzdb는 별도 게이트다.

## Direction contract — 기존 모바일 화면 확장

- THESIS: 금융 알림이 없는 거래를 하나의 수기 입력 흐름으로 보완한다. 미지정도 유효한 거래이며 설정을 강요하지 않는다.
- OWN-WORLD: 기존 Bookify의 밝은 배경·흰 입력면·파란 주동작 토큰을 그대로 쓴다. 새 디자인 체계나 이미지 자산을 추가하지 않는다.
- STORY: 목록에서 직접 기록→금액/날짜→선택 정보→저장 확인→서버 목록 재조회 순서다. 결과 불명은 실패 확정과 구분한다.
- FIRST VIEWPORT: 상단 돌아가기/제목/선택 정보 안내 다음에 방향·금액·날짜를 우선 배치한다. 저장은 모든 선택 입력 뒤의 단일 주동작이다.
- FORM: 기존 흐름의 좁은 확장, code-led. seed는 해당 없음(사용자 Bookify 방향 고정). 선택 목록은 Android Back으로 닫는 모달, 본문은 키보드 위로 스크롤한다.
- FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance. 네이티브 기기 캡처가 없으면 시각 검증 완료를 선언하지 않는다. 기존 DESIGN.md는 변경하지 않는다.

## 예상 변경 규모

제품/시험/문서 약18~25파일 예상, 모바일 폴더 중심. native-client·session-manager를 더 크게 합치지 않고 API 작업/입력/저장/화면으로 나눈다. 현재 DB/서버 제품 코드는 재사용하며 기능 누락이 확인되면 먼저 원장에 남긴다. 운영 DB·배포·커밋/푸시, 알림 listener, 환불/통계, iOS는 이 단위의 완료 조건이 아니다. 전체 목표에서는 그대로 남는다.

실제 구현에서는 화면 공통 제어·오류·경로와 계정별 workspace를 분리하고, 역사적 시각의 공통 wire fixture/DB 회귀를 보강해 약34파일로 늘었다. DB/API/PC 제품 코드는 수정하지 않았고, DB 시험 패키지의 공용 계약 workspace 의존성만 추가했다. 단일 큰 화면 파일 대신 역할 분리를 유지했다.

최종 리뷰 보완: 과거 거주 기준을 선택 입력으로 받아도 전송 payload에 임의 역사 정보는 추가하지 않는다. UTC 시각은 보존하고 장부 날짜를 계산한 후 기존 서버 이력 검사를 통과해야 한다. 목록 확인 표식은 현재 결과 불명 객체와 동일한 조회 시작 상태일 때만 유효하며, 재시도/계정 변경 전의 GET 완료를 새 입력 허용 근거로 사용하지 않는다.

시간대 변환 후속 구현 근거: [Temporal 시간대/중복 처리](https://tc39.es/proposal-temporal/docs/zoneddatetime.html). 라이브러리를 추가하면 버전 고정·의존성 감사·Android 번들/실기기 검증을 따로 수행한다.
