# PC 장부 기본 관리 화면 설계

## 목표와 범위

로그인 후 `/app`에서 실제 본인 계좌·카테고리·프로필 API를 사용한다. 계좌/카테고리의 조회·추가·수정·보관, 닉네임 수정까지 제공한다. 거래 입력·이체·시작 잔액·은행 연결·통계·모바일 네이티브 앱은 별도 후속 작업이다. 이번 작업은 DB migration을 추가하거나 hosted DB에 테스트 데이터를 만들지 않는다.

## 선택한 구조와 대안

- 선택: Next 경로별 화면 + ky + TanStack Query. 브라우저 상태는 폼 내부에, 서버 상태는 사용자별 메모리 캐시에 둔다. 기존 계약과 BFF를 재사용하고 새 의존성을 추가하지 않는다.
- 단일 거대 `/app` 컴포넌트는 파일 수가 적지만 폼/보안/표 책임이 섞이므로 채택하지 않는다.
- 별도 전역 상태 라이브러리는 이후 복합 편집에 유용할 수 있지만 현재 서버 캐시와 폼 상태를 중복 관리하므로 추가하지 않는다.

## 화면

- `/app`: 계좌 목록, 종류/보관 필터, 생성/이름 변경/보관.
- `/app/categories`: 수입·지출 분류 목록, 생성/이름·정렬순서 변경/보관.
- `/app/profile`: 닉네임 수정. 역할·가입 경로는 읽기 전용. 프로필 사진 업로드는 아직 제공하지 않는다.
- Figma 참고 페이지의 흰 상단바·가로 메뉴·청록 강조·회색 바탕·얇은 표 경계를 적용한다. 인증 화면의 기존 60vw 규칙과 색상은 변경하지 않는다. 가짜 거래/요약 수치는 넣지 않는다.
- 키보드 포커스, 기본 HTML dialog, 명확한 label, 빈 상태/로딩/오류, 긴 한국어와 좁은 폭 대응. 숫자는 원 단위와 정렬을 유지한다. 장식 애니메이션 없이 짧은 상태 피드백과 reduced-motion을 적용한다.

## 보안과 데이터 일관성

- 브라우저는 같은 출처 `/api`만 호출한다. 쿠키는 기존 HttpOnly 인증을 사용하고 DB 키/JWT를 노출하지 않는다.
- 입력/응답은 공유 Zod 계약으로 검증한다. 모든 POST/PATCH에는 CSRF 토큰을 붙인다. 원본 예외/본문은 UI에 표시하지 않는다.
- 계정 ID별 query key 및 분리된 QueryClient. 로그아웃/인증 오류에는 화면을 가리고 요청 취소·메모리 캐시 제거. localStorage/IndexedDB/서비스워커를 추가하지 않는다.
- 신원 재조회 중에도 이전 화면을 닫는다. 모든 웹 장부 요청에 expected-user 헤더를 붙여 BFF의 실제 세션 사용자와 비교한다. 인증 헤더가 아니라 추가 일치 조건이다. 탭 복귀 시 미저장 입력을 잃을 수 있다는 비용을 안내한다.
- 로그아웃 처리 중에는 이동 링크를 제공하지 않는다. 완료/실패를 구분하며 늦은 프로필 저장 응답이 비워진 캐시를 다시 만들지 못하게 한다.
- 생성 시 UUID 멱등키는 한 폼 의도에 유지한다. 불확실한 실패 후 같은 입력 재시도는 같은 키를 사용한다. 다른 입력은 새 키를 사용한다. 자동 변경 재시도는 없다.
- 수정/보관은 화면이 읽은 expectedVersion을 보낸다. 충돌은 명시적으로 알리고 새 데이터를 읽어 다시 편집하도록 한다. 낙관적 성공이나 강제 덮어쓰기를 하지 않는다.
- 계좌 추가는 장부용 계좌를 생성할 뿐 은행 연결/실제 잔액 조회가 아니다. 보관은 삭제가 아니며 현재 복원 API가 없음을 확인 화면에서 안내한다.

## 검증

통신/계약/멱등성/세션 경계 단위 테스트를 RED→GREEN으로 진행한다. 실제 Playwright에서 격리된 로컬 테스트 IdP + Next BFF + Nest API + PostgreSQL을 이용해 CRUD·보관·새로고침·로그아웃·비로그인 접근을 검사한다. DB/네트워크 오류와 충돌은 별도 경계 테스트로 구분한다. PC 1440/1920 및 좁은 390px, 접근성/포커스/수평 넘침을 확인한다. 운영 OAuth·은행 API·호스팅 서비스의 실사용 검증으로 주장하지 않는다.
