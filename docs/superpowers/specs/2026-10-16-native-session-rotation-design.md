# Android 세션 자격 증명 교체 설계

상태: Android 우선 구현의 인증 선행 작업. HTTP 로그인 API와 Android 화면은 아직 미완성이다.

## 목적과 범위

웹은 HttpOnly 쿠키를 사용하지만 Android는 서버가 발급한 불투명 자격 증명을 안전한 기기 저장소에 보관한다. 현재 서버는 제공자 토큰만 갱신하므로 Android 자격 증명도 갱신 때 교체하도록 보강한다. 기존 채널·기기 분리 설계를 유지하며 새 DB 열이나 운영 DB 변경은 없다.

## 동작 계약

1. 서버가 고정한 Android 채널에서만 Android 세션을 조회한다. 설치 UUID는 설치 구분값이지 사용자 인증이나 기기 무결성 증명이 아니다.
2. 기존 자격 증명 해시와 버전으로 세션을 읽고 제공자 토큰을 갱신한다. 새 Android 자격 증명은 암호학적 난수 32바이트로 만든다.
3. 한 SQL UPDATE에서 제공자 암호문 두 개, 자격 증명 해시, 버전, 마지막 사용 시각을 함께 바꾼다. 조건은 세션 ID·버전·제공자 세션 ID·Android 채널·설치 UUID·이전 해시·미폐기·절대/유휴 만료 전이다.
4. 저장 성공 후에만 새 자격 증명을 반환한다. DB에는 해시만 남으며 이전 자격 증명은 즉시 조회·갱신·현재 세션 폐기에 사용할 수 없다.
5. Android 동시 갱신의 패자는 `expired`로 실패한다. 저장하지 않은 자격 증명을 성공 응답으로 보내지 않는다. 이후 앱은 갱신 요청을 한 번에 하나만 실행하고 새 값을 안전하게 교체해야 한다.
6. DB 저장 후 응답이 유실되면 재로그인한다. 이전 자격 증명 재사용 유예나 복구용 원문 저장은 도입하지 않는다. 이 UX 비용은 초기 버전의 단순한 보안 경계를 위한 선택이다.
7. 웹 갱신은 기존 식별자와 `refreshed/superseded` 응답을 유지한다. 자격 증명 교체 입력이 없는 저장소 갱신은 웹 행에만 적용한다.
8. 30일 절대 만료는 연장하지 않는다. 전체 로그아웃·비밀번호 복구의 양쪽 채널 폐기 정책은 유지한다.
9. 후속 Android 앱은 갱신뿐 아니라 현재 로그아웃도 직렬화한다. 이미 회전된 이전 식별자의 폐기 결과 `false`를 현재 서버 세션 철회 성공으로 표시하지 않는다. 기기 로컬 자격 삭제와 서버 철회 확인은 구분한다.

## 위협과 검증

- 이전 자격 증명 재사용, 잘못된 기기/해시, 웹↔Android 교차 갱신을 거부한다.
- 갱신과 로그아웃 경합에서 폐기된 행을 부활시키지 않는다.
- 동일 버전 갱신은 하나만 성공한다. SQL 실패 시 일부 토큰만 저장하지 않는다.
- 잘못된 해시 길이, 같은 이전/새 해시, 잘못된 설치 UUID를 DB 쓰기 전에 거부한다.
- 원문 제공자 토큰·Android 자격 증명·실제 금융 데이터는 로그/문서/테스트 자료에 남기지 않는다.
- 이번 작업만으로 탈취된 유효 토큰의 사용이나 악성 앱 복제를 방지한다고 주장하지 않는다. HTTPS·안전한 기기 저장소·서버 폐기·HTTP 요청 제한은 후속 연결에서 필요하다.

## 변경 파일 및 규모

제품 3개: `auth-repository.ts`(저장 계약), `postgres-auth-repository.ts`(원자적 갱신), `session-service.ts`(발급/응답).
테스트 3개: 서비스, PostgreSQL 어댑터, 실제 임시 PostgreSQL 경계 테스트. 문서·진행 보고 별도.
기존 웹 동작 회귀 검증과 코드/보안 리뷰를 수행한다. 클라우드 DB 적용·배포·모바일 자동 수집 완료는 범위 밖이다.
